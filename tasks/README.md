# tasks · 执行者启动指南

> 你（小伙伴）拉取本仓库后，从本文件开始。全程只需 4 步。

## 第 0 步 · 环境（一次性）

- 装 Git 和 Node.js ≥ 18（`node -v` 能出版本号即可，本仓库改造后只依赖 Node）
- 一个能读写文件的 AI 编码工具（Claude Code / Cursor / Windsurf 均可；纯网页 AI 见第 2 步的备选做法）

## 第 1 步 · 拉代码 + 建分支

```bash
git clone <仓库地址> && cd ai-for-design    # 或已有仓库则 git pull
git checkout -b w2/m0-spec                  # 分支名 = 你工作流编号/任务slug，见下表
```

| 你领到的卡 | 分支前缀 | 例 |
|---|---|---|
| tasks/W1-mainline.md | `w1/` | `w1/t1-p0-verify` |
| tasks/W2-components.md | `w2/` | `w2/m0-spec` |
| tasks/W3-node-migration.md | `w3/` | `w3/n1-diff-harness` |
| tasks/W4-docs.md | `w4/` | `w4/d1-skill-md` |

## 第 2 步 · 启动 AI 会话（复制粘贴即可）

在**仓库根目录**打开 AI 工具，发送下面这段（把【】里替换成你的）：

```
你是本仓库 ai-for-design 改造任务的执行 AI。请按顺序执行：
1. 读 SKILL-REPLACE-PLAN.md 文件头「给所有执行本仓库任务的 AI 会话」的规则块，严格遵守。
2. 读 SKILL-REPLACE-PLAN.md 的 §4（架构）、§9（决策日志）、§13（分工与 todolist）。
3. 读 tasks/W2-components.md —— 这是我的任务卡。【替换：W2-components → 你的卡文件名】
4. 读完先回复我：你负责哪张卡、第一个要做的任务是什么、它依赖谁。我确认后你再动手。

我是【姓名】，负责工作流【W2】。执行中遵守五条协作规则：结论写任务卡回写区并 commit、
完成打勾 §13、方案变更只标注「需拍板」不直改方案文档、只动本工作流文件、开工必读顺序如上。
```

**用纯网页 AI（没有文件访问）的备选做法**：把 `SKILL-REPLACE-PLAN.md` 和你的任务卡两个文件的**全文**依次粘贴进对话，再发上面的指令（删掉"读 XX 文件"改为"以下是两个文件"）。

## 第 3 步 · 日常对话节奏

| 场景 | 你对 AI 说 |
|---|---|
| 开始新一天/新任务 | 「继续我的任务卡，当前任务是 M1，开始吧」 |
| AI 提出方案疑问 | 让它把问题写进任务卡回写区并标「需拍板」，然后你去告诉负责人 |
| 一个任务做完 | 「打勾 §13 对应项 + 回写区补结论 + commit」——然后你人工过目 diff 再 `git push` |
| 卡在依赖上（如 W4 等 T1 结论） | 「查 tasks/W1-mainline.md 结论回写区是否已有结论；没有就先做卡内不依赖它的任务」 |
| 收工 | `git push` 分支 + 开 PR（PR 描述附回写区新增条目） |

## 第 4 步 · 合入

PR 由负责人（W1 用户本人）审合。合入后 `git checkout main && git pull` 再开下一个任务分支。

## 三条红线（AI 违反就纠正它）

1. 不许改 `SKILL-REPLACE-PLAN.md` 正文——只有 §13 打勾除外。
2. 不许动别的工作流的文件（文件所有权见方案文档 §13）。
3. 发现的结论/问题**必须落进任务卡回写区**，不许只留在对话里——对话会丢，仓库不会。
