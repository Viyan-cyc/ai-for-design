# 示意园区布局指南
建议采用日间浅色表达，具体风格由项目需求和已有设计决定。

- 先确定展示边界、道路骨架、地块与业务重点，再放建筑；主路连通入口，支路到达设施，不随意穿建筑。
- 本指南用于示意布局，不宣称精确还原。真实地理底景使用[地图接入说明](../map.md)，保留真实坐标映射与比例，大坐标按工程转换约定处理。
- 重点建筑有可识别轮廓，普通背景建筑用简化体块。绿化与道路提供尺度关系，不以密集树木遮挡主体。
- 相机按业务区域而非整个背景底图取景，避免中心主体太小；不同层级场景不混用建筑级和城市级细节密度。
- 按需求加入少量位置标记或线路；业务面板按用户需求提供。真实地图服务的配置、可用性与联网资源边界见[地图接入说明](../map.md)，离线预览HTML不代表地图资源离线。

可选需求示例：“生成一个工业园区示意场景，包含生产、仓储、办公和能源区，道路连接清楚，浅色风格，重点突出能源设施，支持编辑。”

## 风格选择

风格由适用领域指南给出建议，用户明确需求与工程现有设计优先。角色配色与材质意图按领域维护，真实地图的技术入口见[地图接入说明](../map.md)。

## 构图、质量与实现边界


- 首次写场景前明确：主要功能区及连接关系、主体与背景、观察方向、主色与强调色、细节重点。直接落实到代码与场景数据，不额外写报告或让用户逐项确认。
- 丰富度来自主体、辅助设施、地面标识三个层次。通道与作业空间保持连通，不能靠随意增加物体填满空地。按实际资产占地及旋转后范围安排间距；不假设库里所有模型尺寸一致。
- 取景围绕业务范围，相机与控制器目标一致；依据画布宽高比和最高物体计算机位及留边。near/far、控制距离、光源位置与阴影覆盖随实际范围设置。
- 重要内容不能被屋顶、前墙或楼板挡住。总览需要时采用去顶/剖切/分层展示；用户要求完整建筑时保留建筑，并选择满足需求的视角。不要不加说明改变业务楼层关系。
- 使用有限配色与材质差异体现结构；阴影用于表达接触和体积。保留库模型合理的原始材质，不为统一配色强行重涂所有模型。浅色不等于曝光过高，深色不等于设备全黑。
- 按最终视距分配细节：近处主体轮廓、分件与少量倒角优先；远景省略螺丝、锁扣和不可见内部结构。灯具外观不等于每盏都要创建光源。重复对象保留用户需要的独立编辑能力。
- 景深、反射、辉光是可选表达，不默认引入昂贵后处理；不照搬模糊、大片发光线和高反射地面。精密设备优先匹配模型，几何降级保留轮廓与功能特征，不承诺等同精模。
- 3D 风格与业务 UI 分开：仅用户要求数据大屏/业务操作时添加相应面板、图表、状态标记。不要额外添加品牌、水印、字幕和聊天入口。
- 构建与交付按[场景工作流](../scene-workflow.md)执行。本目录是设计指导，不新增生成门禁；实际视觉效果由用户确认。
- 文中的布局尺寸是展示示例，不是消防、生产工艺或港务合规标准。未知领域按上述原则设计，不硬套现有示例。

# 机房布局指南
建议采用明亮工业表达；深色设施展示按用户需求选用。

- 机柜按行/组布置，预留纵向通道和横向联络空间；制冷、配电、运维区与机柜区建立清楚关系。真实冷热通道、供电和消防设计以用户资料为准。
- 机柜宽深高来自模型尺寸；机柜正面朝向按行统一，成对通道根据需求相向或背向，不只追求整齐外观。
- 主体是机柜阵列，辅助是配电/制冷/线槽，地面网格和区域编号为第三层。线槽不盖住全部机柜，线缆无需每根精细建模。
- 总览去顶并弱化前墙，保留少量建筑结构作尺度参照。深色机柜与浅灰地面形成对比；前门、侧板、设备面板有粗糙度和明度区别。
- 指示灯少量点缀，不把所有机柜变成发光灯箱。不默认生成热力图、实时指标或运维大屏。

可选需求示例（仅表达一个项目）：试生成：“生成一个四组双排机柜的机房，带配电、制冷和运维区，浅灰环境、深色机柜，布局清楚、细节精致，支持编辑。”

# 工厂生产

建议采用明亮工业表达，共同规则见[共享设计约定](common.md)。领域重点是工序连接和物流关系。

## 通用布局
收料、生产、测试、包装、出料按需求形成流程；产线可平行或 U 形，留主通道、横向联络和工位操作空间。线边仓、工装架、配电柜应服务相邻工序。近处主体设备保留轮廓和分件，远处简化不可见细节；去顶鸟瞰不让钢梁遮住产线。

## 可选配方：通信电子制造
仅在用户提到通信/电子制造或相应车间时使用，普通工厂不默认生成三个车间。

| 车间 | 可选生产模块 | 连接与布局重点 |
|---|---|---|
| 天线 | 直线装配工位、测试、在线包装；部分单元可配 SMT、屏蔽测试箱、自动分发机、线边仓 | 装配→测试→包装，线边物料靠近工位，测试空间独立可辨 |
| 计算 | SMT、主板装配、整机装配、ICT/FT 测试、液冷测试、老化、BGA 返修 | 主线与测试/返修支线分开；老化柜成组，办公区不挤占物流通道 |
| 无线产品 | 射频模组装配、连接器插件、罩体贴合/紧固、点胶、固化、选择性波峰焊 | 工位顺序依据用户资料，固化设备和周转区对应，不等同无线网络覆盖场景 |

SMT 展示链可采用上板机→印刷机→贴片机→回流炉→AOI；这只是典型示意，真实工艺以用户资料为准。ADM、CAB、1P、4C 等缩写优先依据模型元数据/用户资料匹配，不凭缩写杜撰具体设备结构。

公共区按需要加入 AGV、提升机、电梯、过板平台、工装架、飞达料架、消防设施。冰箱等生活设施仅在用户要求或明确休息区内加入，不用于随意填充画面。

## 数量、检索与交互
数量由项目需求与空间容量决定。以生产单元复用布局，设备占地与间距共享同一份尺寸依据。海康、南江、5G款等具体型号依据库资料匹配，外观改色不能证明型号一致。

AGV 静态布置与自主运行不同：有运行需求才实现路径/动画，不能将轨迹动画称为真实调度。信息卡和产线指标按需生成，模拟数据明确标注。

# 港口示例：清晰的海陆物流关系

本指南描述示意港口的海陆物流关系。配色是未经设计师确认的建议；真实地理底景另读[地图接入说明](../map.md)。

## 设计目标

第一眼看懂海面、岸线、泊位、岸桥、堆场和陆侧道路的关系。可采用日间、低饱和海港表达，主体结构清楚，色彩集中在集装箱和机械设备；夜景和发光效果按需求选用。

## 一份具体的场景草案

可选布局示例（非默认、非合规标准）：岸线沿X轴，海域在-Z侧，陆域在+Z侧；原点可放在展示岸线中段。实际范围由项目提供，岸线几何与业务区域共同决定相机目标。

- 船舶长轴沿岸线摆放，不横穿岸线；岸桥沿泊位排列，悬臂朝海侧，覆盖船舶作业方向。
- 集装箱堆场在岸桥后方，按箱区成组排列；箱区之间保留连续运输道路与横向联络通道。
- 陆侧布置闸口、集卡等待区、仓储和辅助设施；道路连接实际装卸节点，不画成无出口装饰线。
- 重点展示一个作业泊位及相邻箱区，其余区域降低细节，避免每处都成为视觉焦点。
- 宏大感来自船舶、岸桥、集卡与集装箱的尺度对比及阵列纵深，不靠雾遮住大半场景。

具体泊位间距、作业净空与道路尺寸按需求或项目数据确定；这里不提供生产工程合规结论。堆高不超过用户指定层数，箱体与车辆不得互相穿插。

## 视觉方案

以下为未确认的角色配色建议，不作为固定运行预设：

| 部分 | 建议 |
|---|---|
| 海面 | 低饱和蓝青；轻微明暗变化，不做镜面反射海洋 |
| 陆面 | 混凝土灰；道路深灰 |
| 大型设备 | 蓝灰或项目品牌色，结构轮廓与背景保持区别 |
| 集装箱 | 蓝、砖红、绿、浅灰，按箱区有限循环 |
| 安全标识 | 少量暖黄，用于边界与作业重点，不覆盖全场 |

保留库模型原有材质，不强制把所有船舶和设备重涂成同一种颜色。水面优先简单材质/轻量纹理，复杂反射与动态海浪只在用户明确需要时增加。

## 相机与构图

默认从海侧斜俯视陆域，同时看到船舶侧面、岸桥轮廓及后方箱区。岸线在画面中形成斜向引导线，不让整条岸线机械地横切画面正中。

总览以完整业务区域包围盒取景，包含船舶与岸桥最高点；按屏幕比例留边，避免裁掉吊臂。背景海面等装饰性无限平面不参与取景包围盒，避免把主体缩得过小。

透视相机用于规模与纵深；规划图式总览可用正交。按实际范围设置near/far和控制距离。

## 灯光与环境

使用单一日光方向形成设备明暗面，环境补光保持阴影可读。海面与天空使用同一冷色环境，箱体保留适度暖色对比。

雾是可选项，只作用于远端背景，不能让主要箱区失去可读性。大场景阴影优先覆盖重点作业区，不默认让所有远景集装箱都投射高精度动态阴影；也不增加数十个投影灯。

## 首版细节取舍

必须读得出来：岸线、船岸关系、岸桥作业方向、成组箱区、运输道路和车辆比例。
按需要补充：箱体波纹、船舱轮廓、岸边护栏、闸口、编号、少量集卡。
远景可省略：钢缆完整物理结构、每箱锁扣、车辆底盘、逐盏点光源、每片海浪几何。

阵列数量先估算整体资产成本；远处少做不可见小零件，不牺牲用户需要的对象独立选择、移动和材质编辑。不能把“可以实例化”直接当成完整编辑能力已支持。

避免：船舶漂在陆地；岸桥背对海面；箱区没有运输道路；海面占满画面而主体过小；箱体颜色完全随机；全场同等细节导致卡顿。

## 可直接用来试生成的需求

可选需求示例（仅表达一个项目）：“生成一个集装箱港口总览，展示船舶靠泊、岸桥装卸、箱区与集卡运输道路。日间工业风，布局有秩序，规模宏大，主体清晰，支持编辑，不需要复杂海浪效果。”

# 仓库示例：有秩序的工业物流鸟瞰

本指南提供仓储布局与明亮工业表达建议，未经设计师确认。已选风格或用户要求优先。

## 设计目标

第一眼看懂存储、分拣、装卸与物流动线；第二眼看到货架结构、托盘、车辆和工位。主通道与区域边界清楚。日间冷灰、深色、品牌展示或写实风格按项目选择。

## 一份具体的场景草案

可选布局示例（非默认、非合规标准）：地面中心为原点，+Y向上；装卸门在+Z侧，主通道沿Z贯穿，左侧存储、右侧暂存／大件区，靠门为装卸分拣，打包办公沿边布置。实际长宽高由项目提供。

- 左侧按真实货架尺寸排布多组平行货架；组间留横向联络通道，避免从门口到深处只有一条路。
- 右侧按需求放大件或集装箱；未提集装箱时，不为丰富画面擅自加入大型箱场。
- 中间保留连续主通道，车辆不得横堵通道；车辆位置体现转运关系，而非平均散布。
- 装卸月台与门洞对齐，分拣传送带连接暂存和打包区。
- 远处保持阵列节奏，近处选择少量托盘、护栏、叉车、工位补足识别细节。

数量由区域面积、资产包围盒和通道空间计算，不先承诺“几十排”再硬塞。货架及集装箱高度不得穿屋顶。间距采用投影到布局平面的占地范围，转向后重新计算，不能仅使用旋转前宽深。

## 视觉方案

以下为未确认的角色配色建议，不作为固定运行预设：

| 部分 | 建议 |
|---|---|
| 基础色 | 地面浅灰；墙面灰白；钢结构深灰 |
| 识别色 | 货架橙、梁蓝；标线黄 |
| 货物 | 木托盘与纸箱使用少量相近棕色变体，避免彩虹随机色 |
| 材质 | 地面低反射、钢结构半哑光、纸箱高粗糙；玻璃只在需要的部位使用 |
| 辅助标识 | 区域编号、少量通道箭头与安全标线；避免每个物体都悬浮文字 |

模型已有正确材质时保留，色彩通过地面、标线与环境协调。倒角优先给近处主体的轮廓，不给所有货物增加细分。

## 相机与可见性

总览从可同时看清门口、主通道和纵深的方向斜俯视，按业务包围盒及画布比例计算机位和留边；相机target与OrbitControls target一致。

仓库外壳不能挡住主内容：总览默认采用去顶/剖切表达，保留必要的后墙和部分梁架。用户要求完整建筑外观时另按该需求表达，不能静默删屋顶。梁架不要铺满屏幕遮挡货架。

相机距离、near/far、控制距离和阴影覆盖随实际场景范围调整，不沿用小场景的固定距离。完整取景应同时考虑画布宽高比、水平和垂直视野。

## 灯光

使用柔和环境补光与一个主要方向光建立体积感。顶部灯带表现物流节奏，但不要给每盏灯都建立投影灯光；灯带可用自发光材质。重点保证货架内侧不是死黑、地面不过曝、货物之间能分辨。

主光阴影覆盖实际展示区域；阴影清晰度结合覆盖范围与现有画质档位调整，先保证接触关系和层次，后处理按实际需求使用。

## 首版细节取舍

必须读得出来：功能分区、连续通道、整齐阵列、装卸关系、车辆尺度。
按需要补充：货架层板、托盘、护栏、包装台、区域标识。
远景可省略：螺丝、纸箱微纹理、每个灯具独立光源、被遮挡的内部零件。

避免：只摆货架不做区域关系；为“丰富”塞满所有空地；屋顶遮住室内；随机摆放叉车；相同纸箱复制到毫无层次。

## 可直接用来试生成的需求

可选需求示例（仅表达一个项目）：“生成一个大型仓库物流总览，冷灰工业风。包含高位货架、分拣打包、暂存和装卸区。主通道清楚，货物丰富整齐，能看到叉车转运；采用可看清室内的鸟瞰表达，支持编辑。”

## 可选配方：大中型智能仓储物流中心

按用户需求组合高架货架、地面暂存、装卸月台、分拣包装、设备工位、安全设施六类区域。装卸→暂存→存储/拣选→包装→出库连接成可读动线，辅机沿对应流程布置。

- 高架区：先确定每组货架宽深高与层列，再确定货架长轴、组的排列方向和通道方向。“沿 X 排列”不足以同时表达三者。货架组间及端部留出连接主通道的空间。
- 地面区：区分独立托盘、承载货物的托盘和堆叠空托盘。同一承载关系不要重复生成一套独立托盘阵列。数量语义不明且影响可行性时只澄清关键问题。
- 分拣区：直线、转弯、皮带/滚筒输送段与封箱、称重、缠绕、码垛设备形成连接，不把不同设备各摆一排。
- 月台：车辆与门洞/泊位对齐，道路保留通行；充电设施放在通道边安全可达的区域，不堵主通道。
- 辅助对象：工作台、办公、机械臂、提升平台、消防、安防等按实际需求加入。

明确大量实例的总量、承载和堆叠关系，依据资产尺寸计算容量。叉车通道按项目要求与实际作业空间确定，示例不提供通用净宽标准。

大量重复资产需要考虑总体几何、绘制与编辑成本；不能因单模型合格就默认上万实例不卡，也不能擅自减少明确数量。保留用户要求的独立编排与材质编辑粒度。

深色方案可配浅灰地面和橙蓝货架，重点保持内侧可读，灯光参数按实际渲染能力配置。双主题、AGV自主行驶、状态／运单／库龄卡片按需求启用并核对支持。

# 园区无线网络

本领域指基站、小区、覆盖与干扰展示；无线产品制造使用[factory.md](factory.md)。示意园区补读[campus.md](campus.md)，真实地理底景读[地图接入说明](../map.md)，共享规则见[common.md](common.md)。

## 三层组织
1. 物理园区：重点建筑群、道路、水系和必要背景建筑。主体建筑保留识别轮廓，背景用低对比灰白体块；半透明仅在必要处使用，避免多层透明叠加遮挡与性能开销。
2. 通信设施：基站、扇区方向、状态与连接关系具有明确ID和落点。模型匹配与注入遵循[资产说明](../designer-assets.md)；尺寸依据模型与场地确定。
3. 业务图层：用户分布、速率、干扰、覆盖等各自独立，不默认全部打开。图层有名称、单位、图例和数据来源说明。

## 可选配方：会展通信园区
以园区建筑群和会展建筑群为主体，周边简化背景建筑；蓝色人工水系与青灰道路组织空间。默认冷白灰蓝、明亮环境，斜俯视可看清建筑与基站。

渐变晴空、淡雾、圆形展示底座属于可选外观，非地理结构。雾不得遮掉主体；反射地面默认克制。CSM、HDR、软阴影是具体渲染选择，不因领域名称自动增加依赖；用户明确要求时核实引擎支持、离线资源与性能，不能仅写配置就宣称实现。

## 网络语义
- 扇形表示方向性覆盖示意；方向、半径和高度依据数据。缺数据时明确模拟，不能当成真实无线传播计算。
- 绿色正常、黄色警告、红色严重，阈值由业务定义；状态颜色与速率/干扰的连续色带分开，不共用一个含义不明的图例。
- 栅格关联优先使用真实服务基站/覆盖关系。没有关系数据时可显示“最近基站示意”，不能把几何最近当成实际服务基站。
- 远处基站聚合仅在要求或标记拥挤时启用；明确计数是基站数还是小区数，聚合告警等级有一致规则，不能默认一塔等于一个小区。

## 按需交互
栅格点击连线、竖向拖拽数据面板、建筑透明/切面/线框模式、双视口对比均是独立功能。用户未要求时不实现整套功能；已明确要求时不能静默省略。

图层竖向排列只改变展示位置，不改变数据所属真实楼层。建筑透明不等于真正剖切。双视口需要说明对比变量及相机是否联动，并考虑双重渲染成本。示意数据与真实数据分开，不自动新增在线接口。

相机禁止翻到地下时限制对应极角；距离、near/far随业务范围确定。世界单位米，保持资产正面+Z、+Y向上约定。
