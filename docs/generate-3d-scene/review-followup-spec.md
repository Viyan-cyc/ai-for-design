## 1. 目标与审查边界

优先防止交付覆盖用户修改，明确构建边界，再降低默认阅读和重复构建成本。保持模型优先、独立编辑能力、离线交付、统一构建和既有重试额度。

本轮已检查主入口、生成契约、共享设计规范、地图说明、工作区解析、统一构建、装配检查、离线构建和交付打包，以及 gts-ep-coder、ict-coder 主入口。尚未逐文件审查全部引擎、编辑器、地图和资产脚本，未执行完整回归。本文的代码问题依据静态路径，实施前须用当前版本和最小用例复核。

路径除特别说明外，相对 skills/generate-3d-scene/。维护测试放仓库 tests/generate-3d-scene/，不进入默认生成链。

## 3. R1/R2：交付变更保护

涉及 template/scripts/package-delivery.mjs、scripts/lib/workspace.mjs 及必要的工作流说明。

要求：

1. 发布时记录工具管理的文件清单、内容哈希、交付版本与来源工作区身份。哈希包括 source 及预览文件，不使用时间戳代替内容判断。
2. 下一次发布前比较旧交付与该基线。文件修改、删除或出现未知文件时，保留旧目录并返回冲突路径；不得先替换再报告。
3. 标记文件只证明目录归属，不代表覆盖授权。旧版只有 marker 而没有基线的交付不得静默整体覆盖；提供明确迁移说明。
4. 通过交付路径解析旧工作区时检查 source 是否偏离交付基线；有变化则报告最新源码候选，不能默默使用旧工作区。用户明确指定工作区也不能绕过发布端保护。
5. source 被修改后作为新工程使用；不得自动合并两个工程或删除冲突文件。
6. 保留现有临时目录和回滚机制。发布冲突、复制失败、改名失败均保留原交付。路径比较须处理 Windows 大小写及目录边界；不能沿链接越界清理。

验收：未修改交付可更新；修改 source、删除源码、增加用户文件均阻止覆盖；旧 marker 无基线走安全迁移；失败后旧文件字节不变；指定新输出目录可交付；迁移后的 source 可作为工程使用。测试仅使用隔离临时目录。

## 4. R3：装配总超时

涉及 scripts/lib/assembly-check.mjs 与 runner。

优先将打包和装配放到同一受控子进程，让30秒覆盖全部装配阶段；确保超时清理子进程及临时目录。若实现暂时保留现状，必须将文档精确改为“执行阶段30秒”，不得声称整个检查有总时限。两种方案由实施时选择并记录，不能混用语义。

验收：正常装配、打包失败、执行超时分别有可区分错误；模拟慢打包不会突破声明的总时限；partial/UNCHECKED 不转为新门禁。

## 5. R4：锁恢复

涉及 template/scripts/build-offline.mjs。

锁记录 PID、创建时间和可识别的进程/构建身份。并发活跃构建仍必须互斥。不能仅按锁年龄自动删除，也不能仅凭 PID 存在认定原构建存活。无法可靠判断时返回具体恢复提示，由维护命令核实后清理；正常清理仅删除本次持有的锁。

验收：双构建互斥、正常退出释放、强制终止后可恢复、损坏锁有诊断、无权探测进程时不误删活跃锁。覆盖 Windows。

## 6. R5：资源收集语义

先建立含 params.url='https://example.invalid/detail' 的最小业务节点，确认该值只是业务数据时仍被 collect 拒绝的现象。若现有契约禁止此类字段，应记录契约证据并关闭问题，而不是修改实现。

确认问题后，按已知场景配置、资产 manifest、外观贴图字段及 offline-resources.json 收集资源，不递归猜测所有业务字段。保留已有合法资源兼容；无法静态发现的动态资源要求显式登记。地图联网资源继续遵守 map.md 例外，不能把所有 HTTP URL 一概放行。

验收：业务链接不打包；合法贴图和 GLB/glTF 依赖闭包完整；缺失资源、越界路径和不允许的外网模型仍失败；地图 styleUrl 不被当成本地资源；迁移旧配置不丢贴图。

## 7. R6/R7：规则与读取成本

- 明确流畅档默认无实时阴影；共享设计的体积/接触表达是目标，不构成擅自开启阴影的指令。画质配置以生成契约为准。
- 澄清“只检查上传包”的终止状态：检查、等待确认、导入分别对应何种用户意图，避免检查任务自动扩大。
- 保持规则权威位置表。禁浏览器自评、重试和降级等完整规则只展开一次，其余引用。
- 评估将高级动画、复杂布局和性能细项按需读取；保留普通任务必须知道的接口约束和最小例子。拆文件不能导致检索成本反而上升。
- 延续原 spec 第15节的固定阅读链和字符/字节统计。只有实际采集 token 后才报告 token 降幅。

验收：链接有效，关键约束不丢失；普通 GLB、纯几何、已有场景改位置各有明确最短路径；不增加生成检查步骤。用相同任务对照阅读量与工具调用数。

## 8. R8：自定义输入交付（条件扩展）

官方 scenes/stage.json 闭包已经修复，不再重复修复。先确定是否正式支持额外生成器和配置；支持时优先用显式输入清单，而非猜测任意脚本依赖或复制整个工作区。

清单限制为工程内相对路径，拒绝越界和不安全链接，排除依赖、缓存、历史候选。缺失声明输入在发布前报错。验收需在原工程不可访问的隔离 source 中运行自定义生成器。没有实际需求则保留明确边界，不新增机制。

## 9. R9：性能实验

与原 spec 6.1 一致：不为了提速强行接入遗留 verification-cache。

先使用已有 TIMING 和 benchmarks 记录冷/热构建、纯几何、已有模型、仅布局变化的耗时与资源体积，再选择主要瓶颈。候选包括按内容哈希缓存资源编码、装配 bundle，以及减少重复读取和复制。缓存键包含所有语义输入、工具版本和相关依赖；命中缓存不能漏掉依赖变化。发布仍走完整保护和原子替换。

每种候选必须证明冷构建、热构建、输入变更失效、损坏缓存恢复与输出一致性；无明显收益就不采用。资源拆分单独评估 file:// 加载、内存和迁移成本，不在本轮承诺架构改造或收益百分比。

## 10. 实施批次与完成定义

A：R1/R2，先保护交付和源码。B：R3/R4/R5，补边界和故障恢复。C：R6/R7，统一规则并测量阅读链。D：按证据决定 R8/R9。

每批先补最小复现或契约测试，再修改实现，运行与改动相关的已有维护测试。普通生成依旧只走既定统一构建，不增加截图审美验收。维护回归可验证运行行为，但必须区分编译、同步装配、异步加载、保存交互和视觉评价的证据。

完成时回填：实际改动、测试命令及结果、未覆盖范围、兼容影响和未完成项。全部引擎/编辑器/资产管线的全面 review 仍是未完成审查范围；本文完成不代表其完成。
