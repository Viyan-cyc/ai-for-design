# G Design 设计规则

数值唯一维护入口：[tokens.json](tokens.json)。颜色用法见 [color-rules.md](color-rules.md)。

## 选择与引用

- 先满足用户目标、参考图结构、信息层级及关键状态，再选择视觉风格。比较还原度时分别看布局、字体、颜色、密度、图标和交互。
- 业务界面引用 `--color-*` 语义；组件通过 `--g-*` 兼容变量连接语义。基础色板用于定义语义和图表序列，不随意替换功能含义。
- 同一语义在不同主题中同名。深色 UI 是项目兼容方案；不要描述成 Word 已给出完整深色 UI 原值。
- 字号与同名行高配对；正文默认使用 normal。数字可使用 numeric 字体族。公共尺寸引用命名 Token，图形坐标、数据和计算结果保留在业务配置或算法中。
- 间距优先使用规范网格，同类控件统一尺寸；保留既有微间距和特殊组件尺寸时，注明实现来源。
- 禁用、悬浮、按下、焦点、选中及语义反馈分别引用对应状态，状态同时提供文字或图标。

## 毛玻璃材质

- 默认实色；需要局部材质强调时，按需读取 [frosted-glass.md](frosted-glass.md) 并查询 frost-* 分组。
- 先按控件、卡片、浮层选择档位，再决定是否淡彩染色；遵守面积预算、不叠加背景模糊。
- 主色、功能语义与组件圆角保持既有规则；旧玻璃入口通过兼容映射使用新材质。
- 品牌色重点区域且边角留白充足时，按毛玻璃专题的“色块装饰”选择 frost-decoration；保留色块与统一白字，同组默认只选主卡。

## 图表与代码

- 图表使用 charts 分组定义的序列；无障碍方案和延展方案按场景选用，数量超过序列时按原始规范使用尾部色或重新分组。
- 颜色不作为区分类别的唯一手段，同时提供标签、图例或形状。
- 代码语法使用独立 code 分组；不要与普通 UI 色板混用。详细取色与冲突记录保留于 [H Design 颜色规范](color-rules.md)。

## 迭代

改数值后运行 `build_tokens.mjs`，生成 CSS 分层、分组索引和数值表。`--check` 校验生成物未漂移。新增变量需填类型、用途/来源并在前端 bindings 中声明落点；通用规则维护本文件，颜色和毛玻璃细则维护对应专题；不手抄第二份数值。

## 排版、间距与分层

- 字号和行高成对引用 Token；中文左对齐、不按西文音节断词；数字列按位或小数点对齐，必要时启用等宽数字。
- 正文默认 normal，不低于 small；核心正文优先 normal。页面层级依次使用标题和展示字阶，具体值查询 typography。
- 间距采用 spacing 网格；关联信息取较小档，组件内部取中档，模块/页面区段取较大档。同级间距一致，已有微间距注明来源。
- 同层同类元素统一圆角；嵌套时外层圆角大于内层。控件、卡片、高层面板分别使用对应 radius 档位。
- 用 border 的标准/焦点档区分状态，深色独立容器按主题补边框。shadow 按浮层位置和用途选择，避免将投影与背景模糊混用。
- 键盘可达并保留可见焦点；按场景覆盖 loading、empty、error、forbidden、partial、ready。保存反馈区分成功与失败；删除有确认，批量反馈包含数量和失败项。
