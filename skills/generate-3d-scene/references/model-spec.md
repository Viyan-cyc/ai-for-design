# model-spec — 模型规格（默认值与覆盖方法）

> validate-model.mjs 的机器执行面。写 AI 生成模型或评估入库资产时对照本文档。
> 阈值可 CLI 覆盖：`--max-triangles N --max-nodes N --max-texture-size N --max-textures N --origin-tolerance F --height-min F --height-max F`。

## 设计师上传包的检查标准（2026-10-22 起）

设计师上传包走 `designer-assets.mjs` 的接收/检查流程，标准与下方 CLI 维护档不同，由 `lib/model-policy.mjs` 集中定义（RULES_VERSION 2.2.0）：

- **硬违规（禁止确认/入库，可预览）**：模型内含相机或灯光（含未被默认 scene 引用的定义、node.camera、KHR_lights_punctual）；坐标规范违规（bbox.min.y≠0、X/Z 中心≠0、摆放根非零变换，位置容差 0.1m（10 厘米）；旋转/缩放的单位变换要求不变）。整改后重新导出上传，不能用"仍使用"绕过，不静默删除相机/灯光。
- **性能预算（目标告警，显式同意后可继续）**：三角形 简单≤200 / 中等≤500 / 复杂≤1000（默认中等，可调档不可为通过自动升档）；节点（含 Group）≤5；单张贴图边长≤1024；draw_calls≤5（推荐 1）；贴图张数≤4。显示"实际/目标"与影响说明；同意记录绑定模型内容+规则版本+指标，内容变更后失效。
- **状态分级**：通过 / 待确认（名称、+Z 正面、真实尺寸）/ 性能提醒 / 需整改 / 检查未完成。"可使用"要求：加载通过 + 无硬违规 + 必要确认完成 + 已选中 + 超预算已同意。
- **统计口径**：bbox 为资产坐标空间包围盒（含文件内节点变换）；node_count 含 Group/Mesh/Bone 等自身 Object3D；triangles 按拓扑/索引与实例数计；draw_calls 为标准检查渲染的 renderer.info.render.calls（双视角取最大、关视锥裁剪、每视角独立 reset）；texture_count 按材质实际引用的唯一图片源；max_texture_size 读真实图片尺寸。代码与页面共用 `viewer/measure.js`。
- 超过文件/内存安全容量或实际无法加载仍阻断；CPU/GPU 环境失败只是"检查未完成"，不判定文件必坏。
- 旧 art/strict 硬阈值（50k/2048 等）仅保留在独立 CLI 维护路径（下方），不得在上传/消费路径把已同意的性能告警重新阻断。

## 规格表（两档，CLI 维护门禁）

| 项 | art 档（默认） | strict 档（AI 生成） | 类别 |
|---|---|---|---|
| 面数（道具级 prop） | ≤5,000 | ≤2,000 | 性能·硬阻断 |
| 面数（主角级 main） | ≤50,000 | ≤10,000 | 性能·硬阻断 |
| 子节点数 | ≤64 | ≤64 | 性能·硬阻断 |
| 贴图尺寸 | 单张≤2048² | 单张≤1024² | 性能·硬阻断 |
| 贴图张数 | ≤8 / 模型 | ≤4 / 模型 | 性能·硬阻断 |
| 几何 | 必须含 POSITION attribute | 同左 | 性能·硬阻断 |
| 命名 | `^[a-z][a-z0-9_]*$` | 同规则 | 约定·默认告警（strict 阻断） |
| 原点 | 底面中心 y=0（bbox.min.y≈0，容差 0.01） | 同规则 | 约定·同上 |
| 世界高度 | 0.05~200 m 合理区间 | 同规则 | 约定·同上 |

- 档位切换：`--strict`；面数档位：`--profile main|prop`（默认 main）。
- 退出码：`0` 通过 / `1` 规格违规 / `2` 用法或解析错误。

## 每条规格的存在理由

- **面数**：场景总预算 ≤1M 三角（build.mjs 静态估算 + perf-fps 运行观测）。单模型 prop≤2k（多数几百）才能支撑「成百上千物体」的数字孪生规模；
- **子节点 ≤64**：扁平化节点树——深树遍历与序列化成本线性放大；骨架链（mixamorig*）天然超标属告警级；
- **贴图 ≤1024² / 图集优先**（strict）：贴图带宽与显存是批量场景第一瓶颈；art 档放宽到 2048 是第三方资产现实；
- **命名 snake_case**：编辑器槽位层（子网格材质编辑）以**名称路径**为 key——LLM 靠名字定位部件，无名 mesh 退化 `#N` 序号兜底（改名即失效）；
- **原点底面中心 y=0**：摆放语义（position.y=0 即落地）。偏移原点的模型每次摆放都要补偿偏移量；
- **高度合理区间**：单位错乱的第一道防线（cm 当 m 的模型高 179m，一票识别）。

## 米制与坐标

- 全 skill 的场景与资产交付约定：**右手坐标系、+Y 向上、+Z 为资产正面、长度单位为米**。相机自身沿局部 -Z 观察是 Three.js/glTF 相机约定，不得据此把资产正面写成 -Z。
- 标准资产应在制作/导出阶段确认实际米制、正面方向和根节点默认变换（position/rotation 为零、scale 为一）；落地资产原点为底部中心。不要求使用方为每个模型补单位、朝向或落地偏移。存量资产不能仅改 units 字段就宣称符合标准；当前检查能力及历史模型需按实际验证结果报告。内部子节点局部变换和相机局部观察方向不属于需要清零/翻转的资产根节点约定。

## 场景级预算（与单模型规格互补）

| 项 | 默认上限 | 口径 |
|---|---|---|
| draw calls | ≤400 | build.mjs 静态估算 + perf-fps 运行直读；**WARN 观测**（超限不阻塞，须回应） |
| 三角面 | ≤1,000,000 | 同上 |
| 材质数 | ≤32 | 同上 |
| fps | p95 ≥40（真机 GPU） | WARN 观测；软渲染数值不判断 |

`--strict`（build/perf-fps 同款开关）恢复阻断口径。同类物体 >1000 实例才强制 InstancedMesh（≤1000 普通 mesh + 静态几何合并）。

## 与降级阶梯的关系

- 第 4 层「LLM 直写」产出的**实体 GLB**（入库复用）→ strict 档全量门禁（AI 资产是约定纪律的真正保护对象）；
- handler 过程化产物（代码组合模型，不产 GLB）→ 不走本门禁，走 build.mjs 场景预算；
- 入库第三方资产 → art 档（性能硬门禁 + 约定告警记录 deviations）。
