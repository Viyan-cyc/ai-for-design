# 组件如何进入场景生成

设计师交付组件源码与设计说明。开发审核后，先将源码接纳进组件库，完成类型、构建和实际行为验证；随后才同步给场景生成 skill。同步不负责重新创作组件，也不自动注册业务场景。

## 维护者同步

使用当前组件库和目标 skill 的明确路径。组件库应已有开发依赖；脚本在真实副本中构建，不在源库安装或运行构建。

```text
node scripts/sync-components.mjs --src <组件库> --target <generate-3d-scene目录> --work <新的验证目录>
```

先阅读验证目录中的 `changes.md` 与 `proposed/`。首次迁移旧同步脚本的生成文件，可明确添加 `--adopt-generated`；它只接受有生成标记的旧使用页及组件包，拟接管文件会逐项列出。人工文档冲突应先解决，不能强制接管。已有同步清单后不再使用此选项。

确认修改范围后应用：

```text
node scripts/sync-components.mjs --apply <验证目录/sync-plan.json> --confirmed
```

它更新组件包、组件目录和对应使用页，保留其他领域设计资料。源库或目标发生变化时重新准备。失败会恢复本次仍未被其他人修改的文件；并发修改需要人工处理。该流程不是断电恢复事务，也不是恶意源码沙箱，只使用已审查的组件库和本地计划。

不再使用 `--docs-only`：只更新说明而保留旧包可能造成错误配对。包与说明统一准备、统一应用。机器校验记录放在清单中，使用页不堆积审查记录。

## 场景中使用

新建工程沿用 `init --with-components` 和统一 `build-offline`。从组件目录找到导入路径，再按当前生成契约编写业务 handler，并在 scene-profile 登记。已有工程不会自动升级，不能用新模板覆盖已有源码。组件库的可选依赖不一定自动安装；按所用导入入口，在工程 package.json 中明确声明需要的依赖，再走统一构建，不跳过装配检查。

- **Object3D 组件**：明确 create、参数更新及资源释放责任。场景引擎已经登记的网格资源不能再由组件重复释放；有自有事件、动画或外部资源时必须单独落实清理接口。
- **借用宿主的效果**：显式传入宿主对象，保持宿主材质和几何；清理效果自己的资源与回调。不能从类名猜测建筑提取、坐标或动画规则。
- **完整参数与增量参数**：节点 params 表示完整业务状态；对接增量 setOptions 时，先按组件默认值补齐再应用。片段省略 params 保持现状，完整快照省略或清空 params 恢复默认。验证保存后在不同初始状态中重放，不能只比较JSON。
- **保存**：需要保存的结构参数进入节点 params；外观沿用生成器已有视觉层。验证实际更新与序列化，不能仅凭包里存在该类就宣布可编辑、可保存。
- **参数拒绝**：在业务工厂的 `validate(next)` 中调用组件参数校验，不修改现有对象、不保留临时资源。生成器在整批更新和快照导入提交前调用它，防止后一个组件拒绝参数时前一个已经被修改。未登记校验或校验之后的任意运行异常不在此保护范围；这不是通用事务回滚。

直接调用 handle 更新参数不自动接入编辑器的 dirty/撤销链；需要编辑操作时使用明确的编辑入口并验证历史和保存按钮。离线保存 API 成功不能单独证明工具栏编辑流程已接通。

包同步完成、说明可读、场景创建成功、保存恢复通过、设计确认和正式发布是独立结果。离线编辑的“保存”按现有工作流导出修改或保存包，不会自动改写工程源码。

只有新增组件改变了领域组合或设计决策，才修改 scene-design-examples。通用组件更新不自动生成一篇地图、园区或机房设计方案。
