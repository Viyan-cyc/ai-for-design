# generate-3d-scene

## 产物目录

运行环境提供 `artifact-folder` 时将其作为产物父目录；未提供时使用当前工作目录。新项目按需求生成简短英文连字符名称，在父目录下创建同名工程目录；重名自动追加 `-2`、`-3`。名称由 LLM 根据需求确定，初始化脚本负责分配目录。修改已有项目沿用原工程和预览入口，跳过初始化；构建或编辑冲突不通过新建目录绕过。用户明确指定完整新工程路径时，初始化加 `--project-dir`，路径已存在则报告冲突，不自动换名。后续操作使用初始化返回的实际路径。


目标是快速交付清晰、丰富、可编辑的场景。默认输出 index.3d.html 与配套文件和源码；不默认另出二开包或启动服务。

## 意图分流

先区分接收模型、新建场景和修改已有场景。上传模型只是提供资产，不代表生成场景或公共上传授权。

- 只检查上传包：按 [designer-assets.md](references/designer-assets.md) 接收、交付模型清单页、等待回传并导入；成功后回复准备好并停止，不初始化场景、检索或自动入库。
- 上传包附带场景需求：完成资产确认后继续已提出的需求，不重复询问。
- 新建场景：走下方默认生成路径与选材规则。已确认且内容未变的资产复用检查结果。
- 修改已有场景或回传编辑结果：先读 [scene-workflow.md](references/scene-workflow.md)，定位现有工作工程，按变化范围操作。
- 只有用途确实无法判断时才简短澄清，不用一串参数问题阻塞资产接收。

## 默认生成路径

1. 读 `references/generation-contract.md`，再读 `references/scene-design-examples/README.md`，读取共享规范与命中的领域方案。普通生成不通读引擎、编辑器、材质系统或构建脚本。
2. 会话首次运行 `node scripts/ensure-env.mjs`；缺环境按 HINT 安装。无 Node 时按速查中的 install 脚本处理。依赖位于外部环境，生成项目中不创建 node_modules。
3. 按下方「选材与复用」选择资源；上传包的接收、更新与导入命令见 [designer-assets.md](references/designer-assets.md)，仅在涉及资产操作时读取。
4. `node scripts/init.mjs "<artifact-folder>" --name <场景名称> --profile empty --assets referenced --deps external --defer-build`。模型确认后用 designer-assets inject 注入资源，或 --asset-package 指定已确认资产包；skill 不携带模型库。需组件时加 --with-components，由 init 在工程外准备依赖。
5. 读取生成工程现状，局部修改业务 handler、scene-profile 的注册项和 scene-data。设计相机、光照、材质与布局；不要从 demo 模板覆盖现有文件。
6. `node scripts/build-offline.mjs <WORKSPACE_PATH>`。一次执行静态契约、Node 同步装配检查、类型检查、资源检查和离线打包，前置失败不执行后续依赖阶段。编译使用工程外临时输入，结束后清理；项目仅保留源码与预览。工程自身 npm run build:offline 供开发者安装依赖后使用，默认生成使用此统一入口。成功直接交付并停止；TIMING 与非阻塞性能 WARN 不是新门禁。

### 受控生成与构建

有数据或源码生成脚本时，必须通过统一入口执行：`node scripts/build-offline.mjs <WORKSPACE_PATH> --prepare <可执行文件> ...参数`。例如 `--prepare node scripts/generate-layout.mjs`；准备命令的工作目录为 WORKSPACE_PATH，使用直接进程参数，不拼接 shell 命令。多个准备步骤由工程生成脚本串联，任一步失败必须返回非零退出码。直接编辑源码、没有生成脚本时沿用原构建命令。

入口在准备阶段前获取工程锁；准备命令失败则不启动检查和构建。源文件在复制期间或发布前被检测到变化时，本轮失败且不发布旧产物。锁阻止同一入口并发构建，不阻止外部编辑；完成全部计划内修改后再构建，构建期间不编辑输入。异常退出可能留下 `.cache/scene3d-build.lock`，确认其中进程已退出后才可删除，不自动抢锁。原有检查和修复次数上限保持不变。

场景构建后不追加 typecheck、普通 build、lint、浏览器、截图、性能采样、验证报告或审美修复。模型接收的固定缩略图/加载检查与整包确认属于资产阶段，不是场景复核。真实错误按下文处理；未经运行不能声称已验证渲染或交互。

装配检查在独立进程中用真实 Three.js、SceneEngine 与实际 scene-data 执行工厂注册和同步节点创建，限时 30 秒；超时或检查脚本失败按阻塞处理。它不创建 WebGL、不模拟 DOM、不执行动画帧或联网加载模型。捕获 Duplicate slot、提前 finish、材质实例冲突等代码错误；不是浏览器运行或视觉验收。ASSEMBLY 的 partial / UNCHECKED 表示 Canvas、异步模型等未覆盖，不要求因此打开浏览器、重检库模型或改用几何体。RUNTIME: not-run 表示没有验证渲染与交互。页面好不好看、交互是否好用由用户评价，Agent 不自行做视觉检查或审美修复。

## 选材与复用

已确认用户模型包 → 内网合适模型 → 匹配的现成组件 → 复用 procedural 或自定义几何。

用户明确要求“纯几何体”或“不使用模型库”时跳过检索；低多边形、工业风格、数据可视化与快速生成不表示纯几何授权。无上传包也可直接生成，不要求用户先上传。

- 开始编写主要业务对象的几何 handler 前，先从需求提取对象类别（如叉车、货架、集装箱），扣除已确认上传包中已匹配的类别，将剩余类别写入 UTF-8 查询文件，一次执行 `node scripts/search-assets.mjs --batch <查询文件> --brief --json`。不同数量/位置的同类对象不重复查询；无需用户提醒或批准检索。
- 根据实际返回候选的名称、用途和模型信息判断匹配；匹配的库模型直接下载并注入，不重复检查。向量分数高不等于类别正确。没有合适候选才使用组件/几何；请求失败允许降级，但必须说明“检索失败”，不能说“库中没有”。未执行检索不得声称“未命中”。
- 已确认上传包覆盖全部主要对象时不重复查库；地面、墙体、标线等基础结构可直接几何生成，不必为它们查询。组件已经存在、几何更方便、用户要求快速生成，都不是跳过主要对象检索的理由。
- 交付时简短说明哪些主要对象用了模型、哪些使用几何及降级原因；不生成额外报告，不新增构建门禁、浏览器验收或循环改词重试。配置与下载见 designer-assets.md。
- 检索库只存已审核可用模型。候选类别匹配后直接 download → inject 并在场景使用；不执行 preview/import-check/accept-remote，不要求浏览器报告或用户确认。不得因缺少检查报告改用几何体；只有无合适候选或实际下载/依赖解析失败才降级并说明原因。
- 普通 GLB 用内建 asset 分组。自定义加载行为使用 makeAssetNodeFactory，不另写异步加载/克隆/过期处理。
- 组件按用途和编辑粒度选择，见速查的复用表；不要求每次遍历组件目录。
- 节点与槽位的编辑粒度、稳定命名约束见生成契约「类型、生命周期与编辑」与「组合体命名与结束顺序」。
- 代码建模直接写 handler，不生成 GLB 脚本。模型入库校验属于另行请求的维护任务。

## 地理地图（按需）

明确需要真实地理底图时，读取 references/map.md 并启用可选地图扩展；示意园区不自动启用。地图与三维模型在同一场景，Three 固定 0.185.1。地图服务在内网可访问，使用实际配置；不要求离线瓦片包。需要散点聚合或交通热力时再读 references/map-overlays.md，使用 map.overlays 接入，不默认添加演示点或独立面板。

## 数据与修改边界

工程目录、数据字段、坐标和依赖方向以 [generation-contract.md](references/generation-contract.md) 为准。读取生成工程现状后局部修改；不得用 demo 覆盖用户源码、布局、槽位或已保存外观。生成时不修改核心引擎、编辑器、构建与校验脚本。

应用代码与模型资源离线，不使用 CDN 或 fetch 本地文件；地图联网资源例外见 map.md。动态资源登记 public/scene3d/offline-resources.json。用户要求实时数据时才提供业务映射，纯展示不额外实现 MQTT/轮询。

## 验证失败与重试上限

- 同一批交付首次验证失败时，汇总本轮全部已发现的错误，集中修复后重跑；最多进行 2 轮修复重跑，即首次验证加 2 次重跑，最多 3 轮验证。
- 一轮指执行本次交付既定的必要检查；每次针对失败集中修改代码、配置或环境后重新验证，计一轮修复重跑。一轮内不同检查各执行至多一次，不分别计轮；前置检查失败时，不强行执行依赖它的后续检查。本规则不新增浏览器、运行或其他验收要求。
- 每轮修复重跑必须有针对错误的修复。同一错误再次出现，且没有新的诊断依据或可行修复方案时，提前停止；有新依据和方案的，也只能在剩余额度内继续。脚本自身异常或环境失败时，按已有 HINT 处理，遵守原有编辑边界；无法解决则报告阻塞，不反复执行同一失败操作。
- 达到上限仍失败，明确报告“未通过”，说明剩余错误、相关日志及源码位置；不得声称完成、绕过检查或降低验收标准。仅提供已有源码或预览时，标明其验证状态。
- 额度按同一批交付累计，不因切换错误、检查项、内部步骤或对话轮次重置。仅用户提出新的修改任务或明确要求继续时开始新的验证批次；澄清需求或询问进度不重置额度。


## 交付与保存

构建成功后按以下格式交付预览，简短说明双击打开与进入编辑。目录及源码规则见下方「开发工作区与交付目录」。交付时不默认启动服务、输出第二份工程或报告。

```xml
<artifact type="text/link">实际生成的 index.3d.html 绝对路径</artifact>
```

仅将本次构建返回的 HTML_PATH 替换为实际绝对路径，不输出占位符。最终回复只展示这一个预览 artifact；源码与配套资源保留在工程目录，不单独输出源码、目录、报告、压缩包或其他文件链接，除非用户明确要求。

编辑结果回写与离线/开发模式保存差异见 [scene-workflow.md](references/scene-workflow.md)「编辑结果回写」。保存与退出编辑不是同一操作；未经运行不能声称渲染、交互或视觉验收通过。

### 开发工作区与交付目录

项目源码位于 `<项目>/source/`，init 返回的 WORKSPACE_PATH 指向该目录。源码修改、资产注入和扩展启用均在此进行。后续修改沿用当前工程和预览入口；构建更新同项目的 `index.3d.html` 与 `preview/` 中登记的产物，其余文件保持原样。



预览基线只登记工具生成的 HTML 和运行资源；附件与历史文件不归构建管理。单独移动源码时放在新项目的 source 目录，构建输出到该项目根部。
