# 组件创作与设计交付

先按用户要求的交付物选流程。调现有效果走参数调试；要求独立组件源码时走组件创作，即使宿主已有同类能力。已有实现可作为行为参考，获准复用源码时说明来源与改动。仅在宿主启用已有组件属于场景接入。

## 先确定写入目标

- **按路径角色判断写入权限。** 用户指定作场景来源的工程只读，完整复制到外部新工作区后再接入；已有副本作来源时同样处理。同批多个组件可共享一个工作副本。
- **明确指定的写入目标按授权修改。** 从上下文判断用户是否要求直接在某工程实施；仅给出宿主或写入意图不明确时，直接按副本流程继续。
- **第一次写入前说明并核对绝对路径。** 区分原宿主和实际写入目标。宿主副本以核对过的写入路径为准，独立组件以初始化返回的 `WORKSPACE_PATH` 为准，检查编辑、写入型命令的工作目录及输出路径均落在副本工作区内；运行脚本前核对其实际输出位置。原宿主只读涵盖源码、配置、依赖安装、缓存、构建产物、预览和发布输出。副本或构建遇到问题时，在副本内排查，原地接入仍需明确授权。

- **调试已有能力**：读 [debug.md](references/debug.md)。随附页面目前只提供经过验证的 Grid 参数适配器；其他已有组件应使用其已验证独立宿主或明确新增适配，不能宣称通用拖入任意组件。
- **创作新能力**：读 [create.md](references/create.md)。有可构建宿主时用完整副本，无宿主时用原生 TypeScript 模板初始化，LLM负责实现需求，再由页面调整已实现参数。未提供的行为不能靠滑块凭空出现。
- **整理/导出交付**：读 [delivery.md](references/delivery.md)。默认原生模板导出native-component-source源码包和独立参数JSON；旧原型支持component-source源码包及candidate-component演示工程包；已有Grid工具导出其专用preset；scene-recipe目前按契约整理并人工审查，不冒称自动导出已实现。

设计师只需说明六项：方案与场景、布局、默认表现、操作结果、开放设置、效果依据与待定。LLM负责单位、映射、来源差异、依赖和验证；不要让设计师填工程清单。参考源码有明确值时先核对默认值与行为规则；任务要求运行对照时再建立运行基线，不能将猜测曲线称为样式一致。

运行脚本前用 `node <本skill>/scripts/verify.mjs` 核对版本/hash。工具在 `assets/runtime/`，按本skill位置解析，不依赖开发机器路径。Node24需环境已有；不自动全局安装。

运行环境提供 `artifact-folder` 时将其作为产物父目录；未提供时使用当前工作目录。新项目按需求生成简短英文连字符名称，在父目录下创建同名工程目录；重名自动追加 `-2`、`-3`。名称由 LLM 根据需求确定，初始化脚本负责分配目录。按上文已确定为写入目标的既有组件工程或已授权原地修改的工程，沿用现有预览入口，跳过初始化；构建或编辑冲突不通过新建目录绕过。用户明确指定完整新工程路径时，初始化加 `--project-dir`，路径已存在则报告冲突，不自动换名。后续操作使用初始化返回的实际路径。组件id用作新项目目录名。

所有工作限上述工程目录；初始化拒绝覆盖，不通过链接写入共享目录。用户指定的受保护目录、并行任务和发布门禁优先。新源码只在显式开发流程运行，ZIP参数导入不执行或安装未知代码。

每轮交付给出打开方式、已实际验证内容、差异、用户待确认项及简短独立review prompt。原型运行、导出、设计确认、工程验证、发布分别记录；技术测试不代签视觉，用户确认不能扩展到未确认版本。导出不是发布授权。

## 默认预览与回复
创作默认交付预览＋实时调参面板＋重置；无需使用者重复要求。有宿主时沿用副本的预览入口；独立组件工程使用 components/<组件id>/、example/ 和模板预览入口。创作交付以构建和必要的代码检查收尾。由用户打开预览确认画面；创作流程不启动浏览器，不截图、录屏、做像素比对或让 LLM 验收视觉。未经运行标明RUNTIME: not-run，不能称交互已验证。检查分层、故障排查和重试上限见[验证流程](references/validation.md)。
最终回复只提供一个预览artifact：
`<artifact type="text/link">实际生成的预览入口绝对路径</artifact>`
使用构建返回的 HTML_PATH；未提供时按创作流程核对实际产物和打开方式。必须使用真实生成路径；不要把component、preset、controls、说明或目录逐个输出为artifact。除非用户明确要求源码、开发交付或入库，其他源码/ZIP/报告不单独链接。验证范围和用户待确认仍用简短文字说明；需要独立review时直接给prompt，不另生成prompt文件。

用户明确要求交给开发或入库时，在回复正文提供创作工程、具名候选目录、已有源码 ZIP 和单独库演示 的实际路径，供维护者直接使用。入库、同步和场景验收的指令见 [入库与场景接入指南](references/library-intake.md)。

## 组件本体与演示边界
每次创作先明确组件本体、借用的宿主资源和接入接口，写入component-boundary.json。两种创作入口均把本体放在统一的 components/<组件id>/ 下。完整场景副本以可构建源码根为基准（generate-3d-scene 为 source/components/<组件id>/）；独立工程以项目根为基准。每个具名目录沿用原生候选文件结构，场景接线和面板留在目录之外。既有 component/ 工程沿用原入口。交付时在正文给出新增组件源码入口。按需求判断所有权：货架的几何属于货架组件；地图扫光借用地图建筑，不能在扫光组件里重建整座城市。创作的能力本身就是灯光或相机时，这些资源可以属于组件。
组件不得反向依赖example或演示导出代码。宿主通过明确参数/适配接口传入资源；关闭和销毁组件只处理自己拥有的资源，工程接纳时实际验证原宿主仍可运行。不得把演示地图换名移入component来通过检查。
用户确认并请求开发交付或入库时，两个入口统一整理原生候选，见 [入库指南](references/library-intake.md)；默认原生预览中的“导出参数”只导出参数JSON；旧原型的“导出演示工程ZIP”不是纯组件。详情见references/delivery.md。不以导出成功代替工程适配/发布。

新建独立组件工程根目录只保留index.3d.html、components/、example/（已有用户历史保留）。独立组件工程不新增 source/ 或 preview/，也不在交付目录执行npm install。统一运行node example/build.mjs，工具在LOCALAPPDATA下的隔离目录安装依赖并生成中间文件，将JS/CSS嵌入根预览。原生模板使用OctoComponentNative；旧原型使用OctoComponentBuild。构建不等于发布。旧原型不要直接运行example/scripts内部规范化构建脚本，它们由build.mjs在外部工作区调用。

## 面板与维护边界
创作预览使用随附面板模板：桌面右侧参数面板，窄屏从右侧展开且可收起，保持新版场景编辑器的配色、控件和间距。不要另起一套UI或把整个场景编辑器复制进组件。只为实际支持的动画开放播放操作。默认值来自可执行参数定义，控件显示单位与当前值。
本skill仅含使用必需说明、脚本和运行资源；维护源码和测试留在仓库tools/tests，不复制到用户组件。原生组件交付目标见[规范](references/native-contract.md)；默认原生对象模板已提供；native-host提供普通Three Mesh的借用宿主示范；地图自动适配尚未提供。开发确认后的库接纳使用维护工具，见[入库说明](references/library-intake.md)，创作不会自动写入共享库。

借用场景的复制脚本与宿主范围见 [create.md](references/create.md#借用现有场景)。动画及播放控件按需求启用；默认静态，不把附加效果等同于动画。

需要库交互文档时，另附 library-demo.ts（独立模板位于 example/）：右侧实时控件、源码默认恢复和切页释放；演示宿主不进入component源码包。接口及开发交付方法见references/library-intake.md。

## 默认与容错契约

复用组件时沿用内置默认样式，只覆盖用户明确要求的字段及必要宿主/数据输入；新创作组件把确认的样式定义为唯一默认源，面板、示例和导出都引用它。不要把本次场景数据写成组件默认数据。
所有新组件遵守 references/native-contract.md 的失败恢复约定：先验证后提交、更新失败保留状态、构造失败清理自有资源、可选效果失败保留宿主并显示原因。不要把任意错误都“修正”为默认数据。创作预览仍提供右侧实时面板。


### 动画与宿主调度
有动画才提供播放控制；静态组件不强制动画。动画组件管理播放状态，通过宿主统一帧回调接收时间，并声明播放中的帧需求；暂停、结束、隐藏、销毁后解除自身需求，不影响其他动画。播放/重播应唤醒按需渲染。不得自行另开持续循环；后台暂停计时并在恢复后继续。自动播放遵循需求和已确认默认行为，不把 enabled 与 playing 混为一谈。维护验证覆盖首次静止播放和暂停后空闲；日常创作不因此增加截图检查。
