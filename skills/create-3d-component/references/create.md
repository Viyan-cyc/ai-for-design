# 创作独立组件

先读现有工程的源码入口、依赖声明和所需公开接口，确认宿主是Three对象、地图图层还是其他形态。同工程、接口未变时复用识别结果；不默认通读引擎或解析大型内嵌HTML，只有源码缺失或问题确实位于产物时才分析打包文件。

有可构建宿主时走[整工程副本](#借用现有场景)。无宿主时创建独立原生 TypeScript 组件工程：

```text
node <skill>/scripts/init.mjs "<artifact-folder>" <组件id>
```

未提供artifact-folder时省略该参数，使用当前目录。目录重名自动编号；显式完整项目路径用--project-dir，已有路径拒绝覆盖。按 SKILL.md 确定为写入目标的既有工程沿用原目录，不重新初始化。以 WORKSPACE_PATH 为工程根、COMPONENT_PATH 为生成的组件目录。

## 组件与演示
新建独立组件工程使用 index.3d.html、components/<组件id>/ 和 example/。每个具名组件目录包含原生候选 package.json、src/index.ts、src/parameters.ts、设计和工程说明，以及 preset.json（无覆盖时写空对象）。旧 component/ 工程继续使用原构建。组件继承Group，宿主负责场景、相机、灯光和渲染，setOptions修改组件选项，dispose释放自己资源。不要把演示地图、参数面板或渲染器放进组件源码。

初始化只有可调立方体，必须实现用户实际需求，不能把模板叫作完成业务。字段变化同时调整parameters、预览宿主和说明。默认值不在面板中重复硬编码。参数导入的允许字段与版本必须随实际组件同步，保留错误输入不改变当前画面的行为。

自动模板支持object3d与native-host（借用普通Three Mesh）。native-host是轮廓高亮接入示范，不是扫光或地图瓦片成品；MapLibre、蒙皮与实例化几何需另行适配。原生构建当前支持本地TS模块和three peer，暂不支持组件资产、动态导入或其他peer；需要这些功能先实现适配和测试，不能绕过检查。

## 预览和调参
独立组件工程运行 node example/build.mjs；完整宿主副本使用宿主原构建入口。依赖和构建中间文件位于外置真实工作区，不在交付目录安装依赖或建立链接。原始TS类型依赖（含类型导入、导出和引用指令）、类型检查和运行依赖闭包检查通过后生成可直接打开的index.3d.html；构建失败保留旧页面，不能将旧页面称本轮成功。
两种创作路线共用同一调参约定：源码默认值在 src/parameters.ts；预览从组件目录读取 preset.json，合并并校验后作为初始参数。实时修改作用于预览实例，恢复默认回到本次预览初始配置，参数导入导出使用同版本 JSON，导入失败保留现状。完整场景副本把这套面板接在宿主侧。使用默认右侧面板与生成器样式，窄屏可收起。参数实时生效并显示单位，支持恢复默认和同版本参数JSON导入/导出。静态组件没有虚假播放按钮；实现动画时补齐实际暂停、继续、重播及循环接口，并接入宿主调度。
默认构建通过后交付，由用户打开并评价效果；未经运行注明RUNTIME: not-run。按[验证流程](validation.md)区分快速创作、定向排障与工程接纳，不默认追加浏览器、截图或视觉检查。外部网络依赖如实说明。最终只提供一个预览 artifact。宿主构建输出 HTML_PATH 时使用该路径；否则根据宿主构建配置和本轮日志定位产物（例如 Vite 的 dist/index.html），检查文件确实生成在副本或隔离工作区。按宿主原约定说明打开方式。需要 HTTP 时，给出以副本为工作目录的预览命令及访问方式，按服务入口打开；不要把本地 HTML 标成可双击预览。未生成可用入口时如实说明，源码不逐个作为 artifact 展示。

#### 参数文件格式

- 组件目录的 `preset.json` 是裸参数对象，例如 `{"radius":2}`。它只用于构建时为预览提供初始覆盖，无覆盖时使用 `{}`。
- 面板导入和导出使用同一种带身份和版本的文件，例如 `{"formatVersion":1,"id":"pulse-ring","version":"0.1.0","parameters":{"radius":2}}`。顶层字段固定为这四项。`id` 取组件元数据中的 id，`version` 取组件包版本，`parameters` 是该组件公开的参数对象。
- 同一组件、同一版本的参数文件应可在独立预览和宿主预览之间双向导入。先校验格式、组件身份、版本和参数，再应用。任何校验失败都保留当前预览状态。面板导入导出不写回 `preset.json`；若把已导出的值用作初始预设，仅提取其中的 `parameters` 对象。

## 组件交付
用户确认且请求开发交付或入库时，独立组件工程可运行 node example/build.mjs --export-component；完整场景副本可按[入库指南](library-intake.md)直接使用具名组件目录作为原生候选。源码包只包含组件自身源码和资料，Three由peer提供，不含演示或node_modules。预览中的“导出参数”只导出参数，不等于组件源码包。
自动导出保持设计未确认、工程未验证和未发布，不能通过点击导出自动升级。开发接纳前还须在当前目标组件库副本检查类型、构建、公共入口与实际行为。原生源码测试通过不等于已自动入库。

## 借用现有场景

1. 定位完整工程根、可构建源码根、构建命令、必要资源和输出位置。generate-3d-scene 的产物优先检查交付根下的 source/、接入指南及原脚本；其他宿主按实际目录定位。
2. 在原宿主之外创建未占用的工作副本。复制前解析原宿主和副本父目录的真实路径，并核对新目标与原宿主互不包含。拒绝保留或跟随复制范围内的符号链接、Windows junction 等目录重定向；发现链接时先确认如何取得独立实体资源。首次写入副本源码或运行写入型构建前，核对目标、工作目录和输出路径的真实位置（尚不存在时核对最近的现有父目录），确保不落入原宿主。保留源码、锁文件、资产、配置、原目录层级和原发布所需的预览及基线；跳过 node_modules、缓存、历史和非必要中间产物。已有副本作场景来源时同样复制；同批多个组件可共用一个新副本。
3. 用副本的原构建链做基线构建。generate-3d-scene 产物保留副本根下的 source/、预览及其基线，将副本的 source/ 传给生成技能的统一构建入口。按宿主构建约定使用隔离依赖与中间工作区。已有可构建源码时从真实入口接入；仅有打包产物或基线无法建立时，说明缺项，简化或重建须经用户确认。
4. 在副本可构建源码根下统一使用 components/<组件id>/，每个新组件一个目录，初始化时按原生候选的 package.json、src/index.ts、src/parameters.ts、design.md、engineering.md 布局准备。generate-3d-scene 副本使用 source/components/<组件id>/。若其他宿主有源码目录限制，在其可构建源码树内确定一个统一的 components/ 根，同一副本的所有新组件共用它。宿主数据、挂载、调度和面板接线留在组件本体之外。保持组件依赖闭包，借用场景真实资源，保留原内容、配置与交互。地图特有能力仅在组件需要时接入。
5. 完成后用副本原构建链生成预览，做必要的组件类型、依赖边界和逻辑检查。用户打开副本预览确认画面。明确指定原地修改时，沿用授权工程自己的入口。

### 随独立组件工程附带宿主演示

仅在交付采用独立组件工程且附带真实宿主时，使用 native-host 模板和 copy-host.mjs 建立 example/host/，并按需扩展 example/build.mjs 接入宿主构建。对支持只构建的 generate-3d-scene 宿主，在副本源码根为子进程设置 SCENE3D_BUILD_ONLY=1，执行 node scripts/build-offline.mjs，通过 BUILD_COMPLETE 定位 offline/；演示构建入口需要实现产物收集和预览资源路径处理。

## 动画由需求决定
“向外扩散、逐渐消散”等包含动画意图；“添加高亮/边框”不表示要闪烁。native-host默认静态，无播放按钮，无持续刷新。只有需求确实需要动画时加--animation pulse作为动画接线示范，再实现真正业务算法。不要因为模板存在播放能力就自动增加动画或循环。动画宿主调用tick(dtSeconds)；false表示该效果无需持续帧，操作通过invalidate唤醒。暂停、继续、重播和循环只在选择动画时显示。
关闭仅隐藏组件自有组，销毁仅释放自有几何/材质；借用对象的形状、材质、光影和可见性保持。宿主变换后调用syncTargets，几何拓扑变化需重建效果。
