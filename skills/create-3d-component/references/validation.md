# 构建、自验与停止条件

## 快速创作（默认）

独立组件工程集中修改后执行一次 `node example/build.mjs`。完整场景副本沿用宿主原构建，先验证构建基线，接入后再构建交付预览。沿用外置依赖缓存、类型与依赖闭包检查及打包；不在交付目录安装依赖，不重复追加已由入口执行的typecheck/build。构建期间不编辑其输入，也不并发运行同工程构建。

采样预算、分档、插值、时间进度等独立算法按需求使用小数据的Node检查，先覆盖关键边界，不靠冷启动地图诊断数学问题。不为简单参数修改另写一整套测试。

创作交付以构建与必要的代码检查为准，不启动浏览器，不截图、像素比对、录屏或让 LLM 判断视觉。构建成功后由用户打开预览确认画面；未运行说明 `RUNTIME: not-run`，该标记不触发额外验证。构建通过不等于渲染、交互或视觉通过，用户确认也不自动代表工程接纳。

## 定向运行排障

定向运行排障属于另外明确提出的运行检查或报错修复任务。创作交付中出现构建或代码错误，使用构建日志和项目代码检查定位，不因此启动浏览器。缺少浏览器能力时说明未验证，不临时自建CDP驱动、PNG解码器或像素验收平台。

需要浏览器的检查尽量复用已加载宿主和页面；仅参数改变走公开接口，代码改变按开发环境更新，确需完整启动时再重新加载。动画按需支持确定性进度定位或测试时钟，不给静态组件增加播放能力。固定小数据先测算法，再在实际宿主确认集成；不能把小样本通过冒充真实宿主通过。

不默认下载地图瓦片或创建离线缓存工程。已有许可缓存可复用；真实网络问题与组件错误分别报告。文本使用补丁或显式UTF-8读写，避免隐式编码整文件往返。维护工具与证据放仓库tools/tests/docs，不进入组件运行源码。

## 开发接纳

按library-intake.md在当前目标库副本执行类型、构建和必要的实际运行检查：适用的数据更新、参数更新、多组件联动、启停、重置、销毁，以及借用宿主仍正常运行。检查多实例隔离、订阅/共享资源释放；按实际组件适用，不强制所有组件都有动画或数据接口。构建不能代替这些检查，截图也不能证明生命周期正确。默认仍不做截图或LLM视觉验收。

既有Spec明确要求的专项运行回归继续执行；不能以默认快速路径撤销已承诺验收。用户另行要求截图或视觉对照时，按该任务范围执行，视觉确认与技术状态分别记录。

## 重试与交付

同批首次必要验证失败后，汇总错误并集中修复；最多两轮修复重跑，总计三轮。前置失败不执行依赖检查；同错无新诊断立即停，不能反复重建/重开页面碰运气。按同批累计，不因换检查项或聊天轮次重置；用户明确要求继续修复或提出新的修改任务才开始新批次。

达到上限仍失败时如实交代剩余问题和定位，不绕过检查、不交付旧页面冒充新成功。简短区分构建、运行、设计确认、工程接纳、发布状态；不默认输出长审计清单。

### 默认与失败路径
定向验证：省略配置使用默认；仅覆盖一项不改变其他默认；错误数据/参数更新后读取值与画面资源仍为上次有效状态；构造中途失败无残留自有节点/监听；一个可选效果失败不阻止宿主或兄弟组件。诊断可见且可修正后重试。数据组件覆盖setData，依附组件验证不释放宿主。未实际覆盖的历史组件不得声称已全面容错。
