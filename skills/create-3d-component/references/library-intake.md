# 将组件交给组件库

创作完成后交付 `component/`，或将原生源码ZIP解压为同样的目录。解压包的导出清单会校验文件是否完整、是否被修改。演示地图、面板和 `example/` 不进入组件库源码。

开发先审查功能、接口、依赖和资源释放，确定组件归类以及要公开的类或工厂函数。随后由组件库维护者使用仓库中的 `tools/3d-component-studio/intake/cli.mjs`。这是维护工具，不是设计师每次创作必须携带的文件。

1. **查看入库计划**：指定 component 目录、目标库、已有分类和公开名称。脚本列出拟写文件，检查名称和文件冲突，不修改组件库。交互终端中可省略分类，按提示选择。
2. **副本验证**：使用新的验证目录和针对该组件编写的运行测试。工具复制当前组件库，执行类型检查、库构建、运行断言，并生成组件说明。
3. **开发确认后应用**：审阅验证结果与拟写文件，再显式执行 apply。候选或组件库发生变化时，应重新计划和验证。

组件源码原样放入 `src/<分类>/<组件id>/`，分类入口增加指定的公开导出。`docs/components/<组件id>/` 保存自动接口说明、设计/接入说明、设计参数覆盖、组件包信息，以及独立人工文件 `notes.md`；组件库导航和文档索引同步更新。修改参数默认值仍应修改组件源码，不在文档另抄一份。设计参数覆盖用于实例配置，不会暗中改写源码默认值。

首次入库拒绝覆盖已有目录。更新必须显式指定 update；已登记的生成文件若被人工改过，脚本会停止，先处理差异。`notes.md` 可以自由补充，更新不会覆盖。改名、删除、重新分类和新增分类需独立迁移计划。

新增源码或生成文档如果与未登记的既存文件同名，也会停止并指出路径；即使内容相同，重新生成计划或确认apply也不会自动取得该文件的归属。本工具不提供强制接管开关。

当前支持已定义的原生 Three 对象及借用宿主组件、既定 Three peer、无独立资源文件。其他依赖或资源需要扩展契约后再接纳。该流程不会自动发布组件库，也不会自动同步 generate-3d-scene。入库后由维护者按 generate-3d-scene 的 references/component-sync.md 同步包和使用页，再验证实际场景适配与保存。


## 可交互库文档
新创作同时维护 `example/library-demo.ts`：组件源码与演示宿主分离。模板提供独立对象和借用Mesh两种示范；实现业务时须同步修改演示，不能保留无关模板当成业务示例。模板以源码默认值开始，“恢复默认”恢复源码默认，不冒称设计确认的preset。
适配器导出 `initDemo(canvas, controls)`，返回释放函数；通过 `@component` 导入接纳库分类的公开入口，通过 `@parameters` 导入接纳组件参数；允许Three及其addons，不引用候选源码、创作HTML或绝对路径。任意地图/宿主需要明确适配。更新、动画播放及释放语义由适配器负责。
源码ZIP仍只包含component。交付开发时另附此演示文件（保留在example），不混进运行组件；入库plan显式传 `--demo <example/library-demo.ts>`，统一workflow配置填写demo。脚本绑定演示内容，类型检查并打包，生成画布和右侧面板。开发仍需在真实页面验证调参、重置、切页释放；构建成功不等于视觉正确。
旧无Demo候选仍可生成API页，但页面明确提示未提供交互演示，不能宣称完成可视文档交付。已入库Demo的更新必须再次提供演示，不能遗留旧版演示。


## 使用文档内容
类/工厂JSDoc说明用途，@example给出最小可用示例，@remarks只写影响使用的规则与限制；公开方法/属性写清行为、单位及资源归属。LLM随业务实现更新这些说明，不由脚本猜测。示例导入路径须与入库分类一致，分类变更时开发需核对示例。
库页面按用途、Demo、构造参数、属性与方法、使用限制、Examples（最后）生成，空章节不显示，长类型/签名可展开。design.md及engineering.md仍随交付保留，但不再整段铺入库页面。审核状态、来源追踪、入库记录留在维护资料，不放进日常使用说明。已有组件需要将必要使用规则迁入JSDoc，不能仅删文案而遗漏限制。
