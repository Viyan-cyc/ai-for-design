# 体验方向

默认围绕一个明确方向展开；只有用户要求比较方案时才提出多个有实质差异的方向。已知参考和约束继续沿用。

交接使用 assets/insights.json；每个方向保留稳定 id、requirementIds、证据、核心对象、入口、组织方式、旅程改变、收益与权衡。引用 requirements 中真实存在的条目 ID，不编造研究证据。

明确采用一个方向后设置 selectedDirectionId，并把该方向标为 selected；有用户明确批准依据时才标 approved。合并方向时保留原记录和 mergedInto，且 selectedDirectionId 指向最终有效方向。选定方向不等于最终页面已确认。
