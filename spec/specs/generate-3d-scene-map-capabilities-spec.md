## 3. 固定产品约束

- 设计师仍只调用 `generate-3d-scene`；不要求用户选择引擎、填写组件配置或了解工程目录。
- SKILL.md 保持简短，按需求读取领域说明/组件接口，禁止默认读取三个参考 skill 全部内容。
- 普通场景默认 Three；真实地理需求才启用地图模式。出现道路、建筑、园区等词不等于需要真实地图。
- 普通场景不加载 MapLibre、地图网络请求或地图专属资源。
- 保留右手坐标系、米、+Y 向上、资产 +Z 向前；地理坐标通过显式适配转换，不改核心坐标约定。
- 保留已确认用户模型包优先、匹配库模型直接下载注入、无合适模型才组件/几何降级。
- 保留按需渲染、帧率上限、画质档位及高级设置；新动画与图层更新接入既有调度。
- 普通场景仍交付 `index.3d.html` 与必要配套资源及源码，不默认启动服务或生成额外二开包。
- 正常生成只执行现有构建/装配检查；最多两轮修复重跑，不新增浏览器截图、审美评审或视觉自修复。
- 外观是否满意由用户确认；不得把“构建成功”表述为画面或交互已通过验收。
- 维护测试、benchmark、演示工程在 skill 外；生产 skill 不含 node_modules、缓存、日志。
- 本需求不自动修改历史 demo、不自动发布 ZIP、不自动提交。

## 4. 架构决策

### 4.1 一个入口，两种运行模式

`generate-3d-scene` 根据意图选择：

| 模式 | 典型需求 | 渲染所有权 |
|---|---|---|
| 普通三维 | 仓储、工厂、机房、港口、示意园区 | 现有 Three 引擎负责相机与调度 |
| 地理地图 | 真实城市/经纬度上的建筑、设备、覆盖与热力 | 地图适配层统一地图相机与调度，Three 作为自定义图层接入 |

不复制整份地图 HTML 到母版，不并行维护两套互不协调的相机和循环。地图能力作为按需模块；优先同仓库可选入口，不因本需求强制新建仓库。

### 4.2 职责边界

- skill：意图、选材、领域规则、交付流程。
- 可执行预设：有实际参数和应用方法的视觉方案，不只是形容词。
- 3d-components：跨场景几何、散点、聚合、热力等组件，不含业务请求、城市数据和整页 UI。
- 地图适配层：地图引擎、投影、资源来源、相机与共享渲染上下文。
- `business`：真实数据接入、订阅、字段转换、Vue 卡片。
- `scene3d`：场景运行与场景配置，保留既有公共 API 和独立替换边界。

## 5. P1：普通三维场景的可执行视觉基线

目标：先改善当前普通场景结果，不能以地图接入替代此问题。

1. 定向审查现有外观预设和领域文档，合并重复规则，不另建平行且互相覆盖的预设系统。
2. 新增或完善“明亮沙盘”可执行预设：背景、地面、道路、建筑实体、玻璃、绿化、水面、灯光、曝光和阴影必须有统一参数来源及用途说明。
3. 明确材质色与最终成像不同；禁止直接把 MapLibre 的 glow/intensity 等参数映射成同名 Three 参数。
4. 明确主体与背景对比、默认取景、细节等级、道路留白、标签密度。用户尺寸、颜色和构图要求优先于默认值。
5. 做少量可复用建筑构建方法，至少办公楼与厂房两种；稳定槽位、立面朝向/尺寸、窗格间距、屋顶细节受参数控制，避免每次临时造实现。
6. 仍优先匹配资产；建筑构建方法是无匹配模型时的复用方案，不作为跳过检索的理由。
7. 不强制全场统一建筑形状，不以加大曝光洗白、全局雾或大面积发光伪装清透效果。
8. 新建一个小型预览样例供用户评价，不覆盖现有园区 demo。维护样例在 skill 外；用户未评价时标记“待用户外观反馈”。

验收：预设可重复应用；编辑材质和保存导入正常保留；两类建筑支持不同尺寸且装配无槽位冲突；构建成功；不因预设提高默认性能档位；附用户可打开的预览。视觉满意度不由 Agent 自签。

## 6. P2：散点、聚合与热力组件

### 6.1 散点与聚合

- 稳定 ID、坐标、数值和分类输入；选中事件交给业务层，不内建业务弹窗。
- 固定屏幕尺寸的标记按 CSS 像素处理，DPR 只转换一次。
- 聚合成员变化与位置投影分开，连续缩放避免反复跳组；不能将地图 zoom 阈值直接用于 OrbitControls。
- 大量标记使用批量绘制，少量选中卡片沿用现有卡片机制，不为每个点创建 Vue/DOM。
- 更新、可见性、命中、销毁有明确接口；减少运动模式下关闭非必要动画。

### 6.2 热力图

- 先复用现有 HeatMap，明确扩展能力与旧行为兼容性，不默认另写一套同职责类。
- 明确半径单位：世界米制范围或固定屏幕像素；配置和文档不得混淆。
- 数值范围、阈值、色带与单位明确，视口移动不能自行重算 min/max 导致同一数值变色。
- 地图参考的面积模糊缩放是可选展示策略，不改变真实测量场的物理覆盖半径。
- 空数据展示为空/无数据；演示点只在显式演示模式使用并标注。
- 对外提供数据更新及清理接口，重复挂载不遗留资源。

验收：数据替换、空数据、重复 ID 处理、缩放、resize/DPR、拾取、卸载重挂、按需重绘有定向维护测试。记录测试数据规模及环境，不承诺无条件固定 FPS。正常生成不运行这些全量维护测试。

## 7. P3：真实地理地图模式

启动前置：真实需求、内网地图资源来源、网络/离线交付条件已明确。未满足时 P3 保持待启动，不伪造真实地图或悄悄降级为演示城市。

- 统一依赖版本，禁止从参考 HTML 复制 CDN/importmap 保留第二套 Three。
- 明确输入坐标参考系、局部原点、投影、米制缩放及轴向转换；不能将经纬度当世界坐标。
- 地图背景数据和可编辑业务对象分层；不承诺每个底图建筑都能按普通资产拖拽。
- 多轮廓、孔洞等真实建筑几何要正确处理，不能简单填平内院。
- 地图拥有主相机与调度，Three 自定义图层遵守共享 GL 状态和生命周期约定。
- 资源适配覆盖样式、瓦片、glyphs、sprites、字体、模型及必要解码器；服务配置不让设计师在对话中填写。
- 离线与内网在线模式明确区分。需要服务但不能离线时明确说明，不能声称单 HTML 离线可用。
- 按实际资源来源保留必要标注；不直接复制隐藏 attribution 的样式。
- 地图热力适配补齐 setData、重复安装、更新、资源归属与销毁；只清理自己拥有的资源。
- 不携带上海地标、默认示例点和整套演示 UI，除非用户明确要求。

验收：真实来源加载、坐标对齐、视角切换、模型覆盖层、拾取、resize、数据更新、卸载、保存恢复以及对应交付模式可运行。缺少内网环境的项目必须标明未验证，不以 mock 替代实际接入验收。

## 8. P4：统一保存、二开与交付闭环

P1/P2 各阶段先完成自身保存/清理；P4 负责地理模式接入后的跨模式闭环，不允许前期以“等 P4”交付不可保存的普通组件。

- 业务数据和 Vue 卡片留在 `business`；组件仅收数据/配置、发事件。
- 保存稳定 ID、模式、配置、必要数据引用和用户覆盖项，不保存 GPU 对象或瞬时聚合结果。
- 重新加载业务数据后按稳定 ID 应用编辑覆盖；来源变化或 ID 丢失给出明确处理结果。
- 二开指南说明普通/地图模式入口、数据更新、卡片注册、资源位置和销毁职责。
- 组件从源仓库构建并通过现有同步脚本进入 skill，不直接编辑生成的组件文档充当实现。
- 构建和发布只携带所选模式的必要生产依赖；普通工程不得出现地图运行依赖或隐式地图网络请求。

验收：普通模式和地图模式各一个维护样例，完成编辑保存恢复和业务数据更新；普通模式不因新增地图功能增添地图依赖。定向检查脚本、文档、预设、模板和同步产物一致。
