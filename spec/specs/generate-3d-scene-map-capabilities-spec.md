### 用户已确认的实施条件

- Three.js 统一锁定 `0.185.1`，相关类型依赖同步匹配；参考实现适配此版本，不另装 0.180.0，不并行保留两套 Three，也不自行升级版本。
- 内网能够访问地图，按“内网地图服务可用”的条件实施，不再把网络可达性当作待确认的启动门槛。
- 地图可访问不等于已完成实际服务接入。实施时核对服务地址、样式/瓦片/字体/sprite 来源、坐标系及必要配置；未执行真实请求不得标记内网接入验收通过。
- 内网在线地图是受支持的交付方式，不要求为了本需求强制下载完整底图或制作离线瓦片包。页面访问地图服务的依赖应明确说明。

### 已知适配问题

- 地图基线引用 Three 0.180.0；迁入实现必须适配用户指定的 0.185.1，不能混用两套 Three 对象。
- 地图需要样式、瓦片、glyphs、sprites 等资源；依赖安装完成不等于内网/离线地图可用。
- 热力模块已有 source 时不更新数据；destroy 只清理观察器/动画任务，需补齐更新与资源归属。
- 当前 Canvas HeatMap 与 MapLibre 热力图的坐标、半径及渲染语义不同，不直接相互替换。
- 当前 Shape 接口未表达孔洞，不能用实心挤出冒充完整 GeoJSON 建筑支持。
- 上海地标、固定地域、模拟样本和归档流程是示例内容，不能自动进入所有生成项目。
- 地图基线隐藏 attribution；接入时按实际数据源要求处理来源标注。

这些是静态检查结论，实施时定向复核，避免重复修复。

## 3. 整合后的产品行为

### 3.1 一个入口，能力按需组合

用户描述“仓库、机房、工厂、示意园区”时继续使用现有普通三维流程；只有需要真实地理参考或明确地图展示时才加载地图能力，不要求设计师选 MapLibre/Three。

同一场景可以包含真实地图、精细三维建筑与设备、散点聚合、覆盖范围、热力图和业务卡片。地图不是独立产品或孤立页面；无需为使用模型切到另一个生成入口。

没有明确需求，不自动添加热力图、动画、两侧大屏、地标或演示数据。需求不需要真实地图时，不以整合为由引入在线地图依赖。

### 3.2 保留已有约束

- 资产来源仍为已确认上传包优先、匹配库模型次之、组件与几何降级；库模型不增加浏览器复核。
- 右手坐标、米、+Y 向上、资产 +Z 向前。地理投影显式适配，不改变资产标准。
- 业务数据及 Vue 卡片留在 business；场景包不依赖业务实现。
- 保留材质、贴图、模型布局编辑与保存恢复；地图要素的编辑能力需明确界定。
- 保留流畅/均衡/精细、高级参数、按需/持续渲染、帧率上限与性能统计。地图模式需明确每项作用于哪个渲染器；不支持的选项说明原因，不做无效开关。
- 构建通过直接交付；现有最多两轮修复重跑，不增加默认视觉检查、截图或审美自修复。
- 最终用户目录统一为 index.3d.html、preview/、source/；依赖、缓存、中间文件留在独立工作区。
- 普通三维继续支持现有离线交付；地图交付须如实区分离线资源和服务依赖，不能统一宣称离线可用。
- skill 按需加载说明，不把三个 skill 全文塞入 SKILL.md；生产目录不带维护测试、演示项目、缓存或 node_modules。

## 4. 架构与目录职责

| 层级 | 职责 | 不承担 |
|---|---|---|
| generate-3d-scene 入口 | 意图分流、组合能力、选材、生成与交付 | 暴露引擎选择给设计师、默认读全部参考 |
| 地图参考文档 | 有来源的样式/行为规则及接口用法 | 重新创作取代原效果、重复拷贝长篇说明 |
| 地图运行适配模块 | MapLibre 生命周期、相机、投影、图层、共享 GL 状态 | 业务服务请求、整页示例 UI |
| 可复用组件 | 散点/聚合等可独立使用的能力 | 城市名、固定项目布局、业务卡片 |
| business | 数据转换、订阅、业务卡片、状态映射 | 修改核心引擎 |
| 构建与资源层 | 依赖、资源闭包、预览和源码交付 | 把远程缺失伪装成成功 |

地图通用运行能力迁入已有 D:/cyc/project/octo/test/3d-components 的可选地图模块，不新增仓库。通过独立 map 入口及依赖隔离按需引入，普通三维不得因导入通用入口而加载 MapLibre/Turf。地图生命周期、投影、相机和共享渲染协调属于组件库；SceneHandle/Bridge、业务注册、编辑器面板与场景序列化适配留在模板。热力与散点后续按同一边界实现，不先建设过度通用框架。

混合场景由一个明确的相机和绘制调度所有者协调。地图模式由地图适配层协调，Three 模型作为受管理图层；普通模式沿用现有 Three 引擎。不得简单叠两套独立画布/循环假装完成集成。

## 5. 地图体验的具体吸收范围

### 必须迁入或明确适配

- 原 light/dark 配色、建筑表达、道路/水体/绿地层级与标签取舍。
- 二维/三维切换时保留中心、缩放、方位及选择状态。
- 建筑随缩放显露、背景建筑降细节、地标与普通建筑的视觉主次。
- 原有建筑明暗与投影规则，以及必要的缓存与更新时机。
- 地图样式参数具备单一来源；为宿主调整参数时记录差异，不能悄悄替换为新设计。

### 必须区分

- MapLibre 的颜色/阴影/辉光语义与 Three 材质不同，保持各自实现，通过适配协调，不按参数同名直接转换。
- 地图基线中的压缩建筑高度等展示策略只用于明确的地图展示配置，不能修改业务模型实际米制尺寸。
- 上海地标模型可保留为外部维护示例，不成为默认生成内容或预装业务模型库。
- 原整页工具栏、归档版本脚本和审美验收流程不照搬；功能进入现有宿主/编辑体系，避免双工具栏。

验收必须能说明“复用了什么、改了什么、为什么改”，不能只交付一份新写的浅色场景并声称整合完成。

## 6. 散点与热力图

### 散点/聚合

- 按原规范实现固定 CSS 像素尺寸、聚合图形与计数排版；DPR 只转换一次。
- 稳定 ID；聚合分组与投影位置更新分离，连续缩放避免成员来回跳变。
- 大量点用批量绘制，不为每个点创建 Vue/DOM；选中卡片沿用业务注册机制。
- 保留主题、减少运动及缓存要求；主题变化不重置选择和聚合。
- MapLibre zoom 与普通 Three 相机距离不能直接等价，只有实际需要普通三维聚合时才实现对应投影适配。

### 热力图

- 优先复用现有 JS 配置模块。原参考模式保留默认26个色带停靠点、阈值、透明度和模糊规则；普通业务默认采用零密度透明模式，另行验证透明边缘，不强求仍恰好26个停靠点。两种模式均不替换成泛用五色渐变，详见第18节。
- 明确是屏幕显示策略还是物理测量范围；固定屏幕核、视口面积模糊不能冒充真实米制覆盖。
- 数值范围不随视口移动随意重新归一化；数据单位和图例由业务输入明确。
- 提供 setData/update、可见性、参数更新和 destroy；只移除自己拥有的 source/layer、监听和调度任务。
- 空数据与请求失败明确表达；模拟数据仅用于明确的演示模式，不默认填入生产结果。

## 7. 地理资源、模型与编辑闭环

- 明确输入坐标参考系、局部原点、单位及转换；现有模型保持自身标准变换。覆盖地理坐标与资产朝向的定向检查。
- 接入实际地图资源提供方式；外网维护样例可以使用明确允许的来源，不能代表内网真实接入通过。
- 内网 endpoint、资源地址与认证由部署配置/Agent 环境承接，设计师不负责配置工程。
- 样式、瓦片、字体、sprite、模型及解码器的资源依赖分开盘点；地图无法离线时保留说明，不能静默去掉地图或把演示底图当真实结果。
- 统一模型选取、材质编辑、位置调整、业务卡片与保存恢复。底图要素不默认等同可编辑资产，需在界面明确选择/编辑边界。
- 保存稳定要素 ID、坐标、场景配置、数据引用及用户覆盖项，不保存 GPU 对象或临时聚合成员结果。
- 更新源数据后按 ID 恢复覆盖；ID 失效给出明确结果，不按数组下标误套编辑。
- 开发者更新 scene3d 时仍可保留 business；新增地图 API 必须进入二开指南与统一注册入口。

### P1.5：通用组件归位与可选地图模块（已实现）

目标：已有功能不退化，将通用运行能力迁入组件库；不是复制第二套实现。

1. 标签先行：将模板中的 createScreenLabel 迁入 3d-components，保留文字/贴图、CSS 像素尺寸、锚点及深度行为，明确资源释放与所有权。模板只留必要的调用适配。已有深圳工程的修复不等于库迁移完成。
2. 地图模块：先审查当前扩展依赖，拆出 MapLibre 生命周期、坐标转换、相机同步、共享 GL/深度和重绘调度。可采用 @a3d/a3d-components/map 独立入口，名称在实施时确认；接口不得依赖当前工程的 SceneEngine、Bridge、Vue 面板或业务目录。
3. 模板保留：生成场景装配、模型注册、选择/拖动锁、属性面板、撤销保存和业务卡片连接。通过明确接口调用地图模块，不把整套编辑器迁入组件库。
4. 依赖隔离：普通项目无地图导入、构建产物和网络请求；地图项目才准备地图依赖。检查 GSAP/CSG/BVH 等现有 peerDependencies，轻标签不能被迫加载无关能力。Three 使用宿主的 0.185.1，避免两份实例。
5. 发布接入：按现有组件库构建、目录生成及 skill 同步流程接入，核实脚本实际行为。组件实现仅一份，skill 保留调用说明和必要生产依赖；不把源码、node_modules、维护测试塞回 skill。
6. 定向验收：标签覆盖透视/正交、地图共享相机、远近缩放、resize、DPR、父级缩放和资源释放；地图覆盖混合模型拾取、拖动、按需重绘、主题/显隐/锁定、撤销保存恢复及卸载重建；普通三维无回归。数学测试、真实 WebGL 与用户视觉确认分别记录。
7. 同步二开指南、组件目录和使用示例，说明旧工程升级方式；不擅自批量升级用户项目，不发布 ZIP 或提交。
