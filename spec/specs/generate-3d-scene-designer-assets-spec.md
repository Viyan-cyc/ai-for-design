# generate-3d-scene：模型包与内网检索接入规格

日期：2026-10-20（Asia/Shanghai）。更新：2026-10-21。状态：DA-R1～DA-R3 已修复并定向复核通过；真实内网联调及已记录的剩余限制待完成。

本文是本功能唯一有效规格，替换此前同名草案，不保留旧版正文。用户已确认功能方向；本文不表示功能已经实现，也不更改其他优化规格的历史验收结论。当前实现、验证和审查状态以第 15、16 节为准。

## 1. 目标

设计师通过自然语言和可选的模型 ZIP 生成可编辑 3D 场景，不需要了解 JSON、manifest、内部 ID 或命令行。

- skill 的源码分发目录与发布包不携带业务 3D 模型及其贴图/缩略图库。保留代码、模板、必要运行依赖与解码器。
- 常用模型来自内网向量检索库。设计师上传的模型包优先，缺项再查库，仍无合适资产时组件/几何降级。
- 上传整包必须分析全部可发现的模型资产，展示完整预览与描述清单，用户一次确认；不要求逐个填写资料或逐项点击。
- 用户可将确认后的可用资产导出为内网模板要求的 ZIP；真实网络上传由用户在内网接入，首版仅预留接口。
- 保持材质/贴图编辑、拖拽编排、保存导入及离线交付。正常场景构建成功即交付 index.3d.html，不追加审美复核。

## 2. 三条使用路径

### A. 不上传模型包

自然语言需求 → 批量查询内网库 → 判断候选是否适用 → 按需下载模型与依赖 → 缺项几何降级 → 统一构建 → 交付。

无模型包时，不要求上传，不展示模型包确认步骤，也不因内网库未配置而禁止纯几何生成。服务未配置/不可达与检索无结果分别记录；默认简短说明后几何降级。若用户明确要求必须使用特定库模型，则报告相关对象被阻塞，不能擅自用几何冒充。

### B. 上传模型包

附件落盘＋整包说明 → 发现全部资产和依赖 → 校验与预览 → 建议名称/描述 → 完整清单 → 用户确认或集中修改 → 场景选用 → 缺项查库 → 几何降级 → 构建交付。

整包说明示例：“这是我们公司的机房模型，以后做机房设计时用。”不要求逐模型说明。全部资产必须进入清单，包括失败和未命名项，不可只展示识别成功的部分。

整包接收意味着全部纳入资产包，不意味着每个后续场景强制摆入全部资产。用户明确说“本次使用全部模型”时全部可用资产应进入场景；无法使用的资产单独说明，不能静默遗漏。未明确要求全部摆入时，根据场景需求选择，包中适用资产优先。

### C. 明确要求纯几何

跳过内网模型查询。若同时上传包且用途不清，结合原话判断是造型参考还是要求使用模型，必要时只澄清这一歧义，不强制执行模型加载。

## 3. 已核实资料与边界

### 3.1 内网上传模板

依据 D:/Download/file_templete/README.md 与 config.json：

- ZIP 内含 config.json、data/ 资源、image/ 缩略图。
- meta.type 为 file，source_id 必填，group_id 可选；示例中的 16、973 不是通用常量。
- data 条目含 name，以及 file_name、file_path、thumbnail_path、description、tags、search_text、raw_data 等。
- 用户不填写该配置，由导出脚本生成。

### 3.2 内网检索

依据 D:/Download/network/.har 和 tool.html，已观察到：

- POST /lib-resource-service/api/vector/search。
- 请求结构：{type:"file", queries:[...], top_k:N, filters:{source_id, group_id}}。
- 认证头名 octo-vs-token。认证值由宿主/本地私有配置提供，不写入 spec、skill、日志、生成页面或资产包。
- results 对应查询顺序；HAR 为二维数组。工具还兼容每组的 files 字段，适配器应归一化已支持形态，不猜测其他结构。
- 返回候选可含 id、name、description、tags、file_path、thumbnail_path、file_type、raw_data、score、source_id、group_id。
- tool.html 的 top_k≤5 是前端限制，不能据此宣称服务端上限。首版采用 5 的已知请求值，可配置。
- 目标检索范围仅为 3D。此前无 filters 的 HAR 出现其他类型，实施时使用明确配置的来源/分组范围并保留基础文件类型校验，不建设通用非 3D 检索产品。
- source/group 筛选的服务端行为、子分组包含关系、下载鉴权与 glTF 外部依赖 URL 需内网联调确认。group_id 不硬编码为 972，也不默认限制到遗漏其他分组。
- 向量分数用于排序，不是分类正确率。查询“机柜”不能直接采用封箱机候选；允许无匹配。

本轮未实际调用内网接口。实现可用录制/脱敏响应进行维护测试；真实内网联调单列状态，不用本地模拟冒充。

## 4. 职责与存储

| 层级 | 责任 |
|---|---|
| 宿主平台 | 上传控件、附件落盘路径、用户/项目隔离、认证、持久目录授权、可用的视觉模型调用与用户确认交互 |
| skill 接入工具 | 扫描资产、解析依赖、校验、生成预览、输出紧凑目录、归一化库候选、资源复制和入库 ZIP 导出 |
| Agent | 理解整包说明、依据证据建议名称/用途、与需求匹配、解释失败、等待并落实用户确认 |
| 场景运行时 | 沿用现有模型加载、独立实例、编辑、资源释放、离线保存导入 |

附件不可读时必须明确提示，不声称已收到或解析。可读本地目录/文件可作为替代输入。CLI 不模拟一个不存在的网页上传按钮。

资产保存在会话/项目范围的独立目录，绝不写回 skill/assets。用户说“以后继续使用”时，需要宿主提供持久项目或个人目录；若没有，只承诺当前项目可复用，并可导出资产包，不宣称跨对话自动可见。

内网下载缓存与用户包均按授权作用域隔离。只把实际选用的资源复制到工程，移走原附件或断开内网不影响已经交付的离线场景。用户包不自动写入公共库。

## 5. 输入与资产发现

首版支持 GLB、glTF 2.0、包含它们的 ZIP/完整目录。允许单文件输入，不要求 ZIP 才能使用。FBX、OBJ、MAX、BLEND 等列为不支持项，提示导出完整 GLB/glTF；不自动安装转换工具。

发现规则：

1. 扫描 GLB/glTF 入口并解析其引用，建立入口→bin/图像的依赖关系；依赖不是独立模型。
2. GLB 也可能带外部引用，仍检查依赖，不假定单文件必然自包含。
3. 相对路径保留；多个入口共享依赖时可以复用存储，但每个导出资产的依赖必须可达。
4. GLB 中多个 mesh/node 默认属于一个资产，不自动拆成多个业务模型。包含多个 scene 或完整空间时标注“多场景/组合模型”，首版使用默认场景并明确记录；无默认场景时选用可解释的确定规则并在清单提示。
5. 无引用文件列为附属/未关联文件，不计入模型数，也不悄悄删除原包内容。
6. 同名文件按包内相对路径区分。内部 ID 不依赖用户改文件名；稳定包内路径映射与资源内容摘要避免跨包覆盖。
7. 内容去重使用入口及依赖闭包摘要，不能只比较入口 glTF 文本；物理去重不丢失原路径或用户别名。
8. 禁止路径穿越、绝对路径写出、符号链接逃逸与执行包内脚本。展开字节、文件数、单资源大小设置可配置限制，错误以设计师能理解的语言反馈。
9. 上传包的外部网络引用不自动访问；列明需补充的资源。内网检索下载仅访问管理员配置的资源来源，重定向也受此范围约束。

## 6. 技术检查与语义识别

### 6.1 技术检查

分别保存格式、依赖、运行兼容、编辑能力和性能信息，不用单一布尔值掩盖区别。

- 格式/依赖：能解析、缓冲区和图片引用完整、必要几何数据有效。
- 运行兼容：与当前 Three.js 加载器及解码器能力一致；不支持的必需扩展给出明确原因。
- 预览加载：使用共享离屏/受控预览执行器加载资产并产缩略图。每次校验设置超时和资源边界，失败隔离到单个资产。
- 性能：记录几何、材质和贴图成本。资源过重默认告警，不能直接沿用旧公共库艺术资产面数门禁将有效设计师模型全部拒绝；超出明确执行安全限额时才停止该项。
- 尺寸/朝向：记录测量值与来源，不根据尺寸猜单位或擅自改写原模型。布局必要时使用实例变换，尺度不确定可集中询问或允许用户调整。
- 编辑粒度：说明整体移动、网格材质槽位及组合限制。单网格/InstancedMesh/蒙皮对象不承诺不存在的逐零件编辑能力。

UI 状态至少区分：可加载、可加载但有限制、缺依赖、格式/扩展不支持、检查失败/超时。标准格式检查不等于实际渲染已验证；没有真实加载证据时不能展示“已验证可加载”。

### 6.2 语义识别

按成本递增使用：用户整包说明 → 有意义的文件/目录/内部元信息 → 可信已有缩略图 → 模型实际固定视角渲染图。

对 object_001 等无语义名称，不能由面数、顶点或包围盒推断为货车。视觉模型对预览建议类别、名称和简短描述，同时保留不确定项及证据来源，不输出未经测量的置信概率。

无视觉模型时仍完成发现、技术检查和预览，显示“未命名模型 03”等中性名称，由用户看图集中补充。不得静默替换成纯文本猜测。不能依据外形猜设备业务归属、型号、载重等不可见属性。

预览为资产识别所需，不是最终场景审美门禁。默认每个新内容一次固定视角预览，可包含少量多视角合图；不循环截图优化外观。复用已经成功的缓存，失败不无限重试。原始几何/贴图数据不进入 LLM 上下文。

## 7. 全量清单与确认

展示所有发现的模型资产；大包可分页，但总数、失败项、待命名项不能隐藏。每条有稳定可引用的编号。

| 预览 | 建议名称 | 用途描述 | 技术状态 | 识别状态 |
|---|---|---|---|---|
| 图片 | 标准机柜 | 放置服务器的柜体 | 可加载；整体/材质编辑 | 待确认 |
| 图片 | 配电柜 | 疑似供配电设备 | 可加载 | 类别不确定 |
| 图片 | 未命名模型 03 | 柜状设备 | 可整体使用 | 待命名 |
| 错误占位 | 模型 04 | 暂无法识别 | 缺少 cabinet.bin | 无法识别 |

- 提供“确认全部，继续使用”，并支持编辑名称/描述及自然语言批量修改。
- 所有条目经过同一个整包确认点，不要求逐项点击。用户修订后只更新受影响记录。
- 用户消息“第二个是精密空调，其余没问题”可作为这版清单的确认；只有修改意见但未确认其他项时不擅自认为整包已确认。
- 确认绑定清单版本和文件内容摘要。文件更换后相关确认失效；只改描述无需重跑几何检查。
- 确认不覆盖技术错误。不能把坏文件标为可用；用户可以明确继续使用有效子集，失败项保留清单。
- 待确认期间可独立准备需求布局，但不把猜测的语义作为已确认资产生成最终场景或公共入库包。
- 首版可由宿主展示 Markdown 图片表并接收自然语言确认；宿主已有表单能力时可适配。独立复杂资产管理前端不是本轮前置要求。

## 8. 统一资产候选与选用

上传包和检索库转换为同一内部候选结构：稳定 assetId、来源、显示名称、描述/标签、入口、依赖列表、预览、技术状态、语义来源、确认状态、尺寸及单位状态、内容摘要、编辑限制。

字段是内部协议，不暴露给设计师填写。原始服务响应、长向量文本和二进制不直接发送给生成模型；列表返回紧凑摘要，详情按需读取。

选用顺序：明确指定资产 → 已确认上传包中的合适资产 → 内网候选 → 组件/几何。存在包并不禁止为缺项查询库；库分数不能覆盖用户明确指定。候选不适用时允许拒绝，无须“选第一名凑数”。

在调用真实模型加载前将选用资源物化到工程，生成运行时需要的资产清单；不得让离线运行依赖检索服务或授权 URL。复用现有 makeAssetNodeFactory、资源生命周期、槽位和离线构建机制，不另写第二套引擎。

## 9. 入库 ZIP 与预留上传接口

只有用户选择“导出入库包/加入检索库”才生成对外提交包；确认用途不等于授权公共共享。

输出形态：

```text
asset-package.zip
├── config.json
├── data/
│   └── <stable-id>/model.gltf + bin/贴图依赖（或 GLB）
└── image/
    └── <stable-id>.png
```

自动生成：

- meta.type=file；source_id 来自目标库配置，group_id 可选。缺少必需配置时明确要求管理员配置，不填示例值冒充。
- data.name 使用用户确认名称；file_name 保留可理解的展示名；file_path 为实际入口的包内相对路径。
- thumbnail_path 指向已有有效预览；没有预览则省略，不填坏链接。
- description/tags/search_text 使用确认后的整包背景与单模型描述，不加入猜测的业务事实。
- raw_data 可包含实际测量的格式、尺寸/单位状态、几何成本、内容摘要等；不导出凭证、本机绝对路径或未确认推测。
- 多文件依赖布局与 URI 自洽；用户不用逐文件修路径。坏资产默认不提交，明确告知排除项；用户要求整包全部入库且有坏项时报告未完成，不把子集说成整包成功。
- 写入失败不覆盖上一份有效包；产出前核对每个 file_path、thumbnail_path 和模型依赖均可在 ZIP 内解析。

预留 UploadAdapter：输入为生成的 ZIP 路径、目标库配置及宿主提供的认证上下文；返回 not_configured/submitted/failed、可选 jobId 与提示。不内置真实 HTTP 上传，不使用 HTML 中的固定 token。默认返回 not_configured，用户可手动上传。

默认文案：“入库包已生成，可前往内网上传。”未来适配器返回 submitted 也不能直接宣称已可检索，索引就绪需独立证据。真实上传、轮询和服务端回滚不在首版实施范围。

## 10. 工程修改范围与迁移

- 新增或收敛资产接收、预览、候选归一化和入库导出模块；优先复用现有解析/校验/打包能力，不强行复用旧 manifest 强约束入口。
- search-assets 与 init/资源注入改为支持统一候选和工程资源目录；默认不依赖 skill/assets/search-index.json 或内置模型。
- 业务模型、库索引、业务缩略图和模型纹理从 skill 分发中移除。解码器、代码生成纹理工具及运行模板保留。
- 移除前先盘点旧 demo、默认场景、维护用例及运维脚本的依赖。迁移已有资产到用户指定/明确说明的外部位置，校验后移除分发副本，不直接销毁原库。
- demo 改为无业务模型依赖或明确外部 fixture；测试所需小模型由测试生成或放在 skill 外维护目录，不能重新进入发布包。
- 清理旧的“内置 59 模型”、本地库优先、要求用户 manifest、过期手工拷 glTF 目录等文档。维护兼容入口可以保留，但不得作为默认设计师流程。
- 不修改其他 skill，不重写引擎/编辑器，不改共享依赖安装策略。

| 阶段 | 内容 | 完成证据 |

| B | 校验、预览、语义适配、全量确认记录 | 正常视觉与无视觉两条路径，确认版本与局部修订测试 |

每阶段填写实际修改、执行命令、结果与剩余限制；一次集中修复该阶段发现的问题，不因单次样例扩大成新的通用框架。协议在 A 阶段确定，后续实现不另建重复的数据模型。

宿主待配置项：附件路径交付方式、持久工作目录、预览执行能力、视觉模型能力（允许没有）、检索端点/来源范围/认证。真实上传适配由用户后续在内网实现。

这些配置未齐时可实现和测试本地工具及适配边界；真实能力未验证的项保持未验证，不能以 mock 成功记为内网验收通过。

## 12. 验收矩阵

1. 无上传包：只给需求即可检索/降级生成，不要求包或确认表。
2. 纯几何：不请求检索接口，生成流程正常完成。
