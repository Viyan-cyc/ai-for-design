# generate-3d-scene：离线 HTML 预览与精简交付规格

日期：2026-10-19。状态：已实施并完成定向验证。当前任务单元：默认离线交付、编辑保存与维护回归已完成。

本版替代本文旧版“默认启动开发服务”的方案。用户已确定：入口命名 index.3d.html；像 gts-ep-coder 一样双击预览；保留编辑能力；失败最多修复重跑两轮；构建通过直接交付，不要求浏览器、截图或交互验收。历史 optimization Spec 的 P6 未决风险不因本规格而自动关闭。

## 1. 目标与非目标

输入需求后，快速生成精致、有合理布局的 3D 场景。有合适模型优先复用，没有则组件/几何体拼装。默认交付一个可双击打开的 index.3d.html 入口及其配套资源，离线查看、改材质、选择贴图、拖拽编排、保存并恢复编辑结果。

“一个 HTML”指一个入口，不要求所有内容塞入唯一文件。允许配套 JS 和资源目录，整体复制后仍能使用；用户只需点击入口。不需要启动服务、安装运行环境、访问 CDN，或放宽浏览器安全设置。构建工具仍可依赖 Node 和已安装依赖；离线要求针对交付物运行。

不重写场景引擎/编辑器，不修改仓库 demo，不新增建模工具链，不自动部署，不默认生成第二份源码工程，不追求固定截图评分或未经测量的提速百分比。

## 2. 已核实的现状

- gts-ep-coder 的预览有 HTML 入口和配套本地运行库、preview-data.js，并非完全独立单文件。借鉴其打开方式与交付流程，不照搬浏览器内 SFC 编译实现。
- 3D scripts/build.mjs 是静态契约检查。template/package.json 的 npm run build 才执行 vue-tsc 和 Vite。不能仅静态检查通过便声称真实构建通过。
- 当前入口有动态 import，asset-manifest 使用 fetch，模型/纹理由加载器读取 URL。普通 Vite 产物改个名字不能保证 file:// 可用。
- MaterialParams 的贴图上传调用开发服务 /__gts3d/upload-texture。离线模式必须提供浏览器本地读取与持久保存方案。
- strip-edit.mjs 已能复制源码、剥离编辑器、自动编译已保存外观、检查后发布二开包；无需再让 LLM 手工转录。部分引用文档仍沿用旧说明，需要同步。
- SKILL.md 和 references 对默认截图、冒烟、人工清单及修复循环存在冲突，需要一起改。

## 3. 默认流程及交付契约

需求理解 → 有界资产检索/降级 → 生成工程 → 统一检查和离线构建 → 交付 index.3d.html 链接 → 停止。

1. 信息足够直接生成；相机、配色等采用合理默认值。仅核心需求歧义才提问，不为每次场景生成另写 Spec，不要求读完全部 references。
2. 保留精确模型、近似复用、组件、几何拼装的顺序。无命中及时降级，不无限搜索或擅自引入新工具链。
3. 首次生成即考虑布局、尺度、光照、材质、相机、重复物体复用。取消视觉验收不意味着省略场景设计。
4. 一个统一命令执行必要静态契约检查、类型检查、离线网页编译和资源完整性检查。复用已有检查与 Vue/Vite 配置能力，避免重复 typecheck、双重完整构建。为工程新增明确的 build:offline 命令；旧 build 和开发模式保留兼容。
5. 成功条件是本轮所有必要阶段通过、当前产物已发布。无需启动服务或打开页面。最终给 index.3d.html 的可点击绝对路径，并简短说明双击打开、编辑入口及保存方式。
6. 默认不执行浏览器/CDP、截图、视觉评分、交互验收、性能采样、自动美化、strip-edit、第二份工程构建、验证报告或人工验收清单。
7. 不将已有 scene runner 的 preview 档直接当成新默认路径：其可能包含浏览器检查。保留显式诊断/维护入口，默认不调用。
8. 用户明确需要源码联调或指定端口时可启动开发服务；明确需要纯运行源码包时才 strip-edit；明确要求部署时才走部署流程。不能悄悄用服务链接替代承诺的离线 HTML。

文案统一使用“工程目录”“预览文件”“编辑”“保存”等用户能理解的名称，不向用户暴露脚手架内部目录术语。不为术语调整破坏现有 CLI 参数。

## 4. 离线实现约束

### 4.1 代码与资源

- 推荐构建期预编译 Vue/TypeScript，输出可通过普通 script 加载的浏览器 bundle。离线产物不得残留依赖 file:// 模块加载的 import、运行时 SFC 编译或联网依赖。
- 用专用离线入口整合查看/编辑模式；必要动态分块在离线构建中合并。复用同一核心与编辑器代码，不能维护第二套场景实现。
- 场景 JSON、资产清单、模型、纹理及必需解码资源在构建时收集，输出可由本地脚本载入的资源数据。可采用数据脚本配合 Blob/Data URL；不能简单搬运文件并继续 fetch 本地路径。
- 资源收集以实际场景引用为起点，递归包含 glTF 的外部 buffer/texture、相对依赖和已使用的压缩解码资源。复用现有模型槽位/多文件资源处理能力，不能只支持纯几何 demo 或只支持单个 GLB。
- URL 归一保留目录语义，正确处理嵌套路径、同名文件、空格与中文路径；不能只按 basename 建表。HTML 移动到另一目录后仍可用，不含构建机绝对路径。
- 通过集中资源解析接口适配离线和开发环境；保留 makeAssetNodeFactory、骨骼克隆、槽位覆盖及资源所有权约束。不得粗暴全局劫持 fetch 或放开浏览器安全策略。
- 每个实际用到的资源只打包一次，重复模型复用资源；不塞入整个模型库。按需创建解码后的 Blob，管理 URL 生命周期，避免替换贴图/恢复场景后泄漏或提前释放共享资源。
- 不得回退到 CDN。遇到当前运行时不支持的格式，生成阶段可使用已支持资产或几何替代并说明；打包阶段不能静默漏掉资源后报成功。
- 输出发布应避免半成品覆盖上次成功版本。失败时旧文件即便仍存在，也不能当成本轮成功交付。

### 4.2 编辑与保存

- index.3d.html 默认展示场景，提供明显的“编辑”入口。file:// 下切换编辑不得跳转到根路径 /，也不得依赖服务器路由。
- 保留材质参数、现有纹理槽位、物体移动/旋转/缩放、撤销及现有编排能力。
- 离线选择贴图通过 File API 读取，不调用开发服务上传接口。失败显示具体原因，不吞错。开发模式现有上传方式继续兼容。
- 扩展现有 SaveService/导入流程：默认下载一个带版本号的场景保存文件，包含完整场景快照、编辑外观与材质库、新增贴图数据及稳定资源 ID。再次打开原 HTML 并导入文件，应恢复相同场景与贴图。不得将会失效的 blob: URL 或本机文件路径作为持久资源引用。
- 保存文件引用预览自带模型时须带来源/版本校验信息；导入到不匹配的预览应明确报错，不静默丢模型。无需每次保存重复嵌入全部原始模型。
- 保留旧 scene-data.json 导入兼容；缺少外部纹理时明确提示。新保存格式不能直接破坏现有引擎快照 schema，应在保存层封装/解包。
- 不以 localStorage 或特殊文件系统权限作为跨次恢复的唯一机制。普通浏览器下载/选择文件即可完成。
- 保存不自动覆盖工程源码，也不自动改写原 HTML。界面明确“保存文件/导入恢复”，不要暗示已写回源工程。保存后重新打开无需重新构建。

### 4.3 基本故障呈现

复用现有加载状态和错误显示；离线入口初始化失败、资源缺失或 WebGL 不可用时，应显示可理解的错误，避免静默空白。新增包装仅覆盖本次离线边界，不扩展成自动诊断/修复系统。构建通过仍不等同于任意设备绝不白屏，不宣称未经执行的运行时验证。

## 5. 构建失败策略

“构建一次”指统一命令的一次完整尝试；静态检查阶段失败也计数，避免不同子阶段各自重置预算。

1. 首次失败，汇总本次实际输出的全部错误，集中修复后重跑；不要求提前发现被首个错误阻断的其他错误。
2. 最多两轮修复重跑，即最多三次构建尝试。每次成功立即退出循环并交付，无成功后的自动修改或再次构建。
3. 针对错误修复后，同一位置、同一原因的错误仍连续出现且无实质进展，提前停止；仅错误码相同不算同一错误。
4. 脚本自身异常或环境失败，退出场景代码修复循环。按脚本提供的处理提示（HINT）解决或报告阻塞，不修改 skill 检查脚本以求过关、不禁用检查。确需再次调用统一构建时仍计入三次上限；提示不能重置预算。
5. 上限后仍失败，明确“构建未通过”，列剩余错误、源码位置及已尝试内容，不声称完成，不交付旧产物冒充新成果。
6. 美观未知、没有截图、性能 WARN 均不触发修复。用户后续主动修改或继续修复属于新请求，不自动延伸原循环。

## 6. 改动地图与实施顺序

## 7. 本次维护验收（不是每个场景的生成门禁）

新离线运行路径不能仅凭构建宣称正确。本次开发需要一次实际浏览器功能验证；以后普通生成不执行此步骤。测试功能结果，不做截图审美评分。若实施环境不能运行浏览器，明确回填“离线功能未验证”，不可标为全部完成。

- 使用默认安全设置的 Chrome/Edge 在 Windows file:// 打开产物；断网可运行，不依赖本地 HTTP 服务。覆盖带空格/中文目录以及整体移动目录。
- 最小夹具覆盖几何降级、重复 GLB、嵌套多文件 glTF（外部 buffer/纹理与同名资源）、当前支持且实际使用的压缩资源。检查无缺失模型/材质、无远程请求和本地 fetch 失败。缺资源构建必须报错。
- 离线进入编辑，改变材质、应用本地贴图、变换物体并撤销；保存、关闭页面、重开并导入，确认状态和贴图恢复。重复导入/替换不积累无主 URL；共享资源不被提前销毁。
- 旧 JSON 导入和开发模式做受影响回归；无关编辑器全量用例无需重复。确认离线资源层不破坏 strip-edit 与 scene-core/edit 隔离。
- 默认生成命令路径确认不启动浏览器/服务、不截图、不生成第二工程或报告。校验成功一次、失败后成功、三次失败封顶、无进展提前停、环境失败、旧产物不冒充当前成功等分支；若循环是 skill 指令则检查指令一致性，勿伪造执行器测试。
- 记录一个小场景与一个模型较多的现有夹具：构建耗时、产物大小、维护验证中的可见首帧时间；只报告实测环境和数值，不承诺未经验证的速度提升。资源应去重且不整库打包，明显回退须说明。

一次性维护验证与默认生成流程必须在文档中明确分开，不因修改了场景数据或核心文件便默认触发浏览器验收。

## 8. 用户交付文案

成功：“场景已生成，构建通过。预览：[index.3d.html](实际绝对路径)。双击打开，可进入编辑调整材质、贴图和物体位置；保存后可通过导入恢复。移动时请保留配套文件。”

失败：“构建未通过（已尝试 N 次）。剩余错误：……；源码位置：……。”

普通生成不额外附报告，不声称已验证浏览器渲染或绝不白屏。用户反馈效果后再修改。

## 10. 实施回填（2026-10-19）

### 实际改动

- scripts/build-offline.mjs：统一入口，静态检查通过后调用工程离线构建；单次执行，无浏览器、服务、导出二开包或自动重试。
- template/scripts/build-offline.mjs、package.json、offline-entry.ts：类型检查 + Vue/Vite IIFE 编译，输出 offline/index.3d.html、JS、CSS；收集实际资产、glTF 外部依赖及 Draco 解码文件。额外动态路径可用 public/offline-resources.json 显式声明。锁与暂存发布保留上次成功结果，拒绝覆盖非本脚本拥有的 offline 目录。
- scene-core/offline.ts、asset-manifest.ts、boot-scene.ts：场景数据直接读取离线包，Three LoadingManager 集中解析资源；按需创建共享 Blob URL，页面卸载释放；不劫持 fetch。兼容 Node 维护工具和原开发环境。错误显示在页面，不触发自动修复。
- main.ts/edit-main.ts：避免合并为单个 bundle 后两个入口同时启动；维护诊断口仅在开发态或显式 debug=1 下提供。
- MaterialParams、SaveService、Bridge、Toolbar/EditApp、message.ts：本地选择贴图，保存包含版本/来源与去重贴图的 scene.3d.json，导入校验后通过既有快照恢复逻辑应用，支持撤销。错误用可关闭的提示呈现。原开发服务上传路径保留。
- init.mjs 新增 --defer-build，准备依赖后不先编译空场景；现有默认参数行为兼容。init/strip 排除离线输出与暂存文件；strip 同时去掉离线编辑预览入口和命令，保留正常纯运行网页构建。
- SKILL.md、scene-workflow.md、verification.md、scene-engineering.md、README.md：默认构建后直接交付；最多两轮修复重跑；默认不浏览器、不截图、不交互验收、不自动美化、不双包/报告。维护回归和用户请求诊断独立保留。修正自动外观转换的过时说明。
