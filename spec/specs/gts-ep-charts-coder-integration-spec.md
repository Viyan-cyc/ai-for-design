# gts-ep-charts-coder 图表设计集成 Spec

日期：2026-10-29。状态：首版 0.1.0 已实现并完成工程集成验证；未发布上架。结果与未验证范围见 [验收记录](../handoff/gts-ep-charts-coder-0.1.0-validation.md)。下文保留实施规格，事实以验收记录为准。

## 1. 目标与范围

新增独立 skill `gts-ep-charts-coder`，将 chart-design-expert 的分析方法、图表规范与数据语义，接入 gts-ep-coder 的 Vue 3 + Element Plus 工程能力。用户通过一个入口生成、修改图表及图表页，得到标准 src 源码、离线预览和真实验证记录。

本期只实现 EP；`gts-sweetui-charts-coder` 列为后续遗留，不创建其目录，不为其提前抽象共享框架。

不替换或改名 gts-ep-coder；不在运行期调用另一个 skill；不默认新建 Vite 工程；不照搬 FastUI 的 yarn、new-session、verify、export-zip 或 Lake 约束。当前交付不承诺完整可独立 npm install/build 的应用工程，标准源码按实际接入说明交给开发。

## 3. 组合及分发决策

第一版采用独立打包、资产复制（vendoring），与 chart-vue-creator 的首版模式一致：

```text
skills/gts-ep-charts-coder/
  SKILL.md
  design/                 # 上游设计资料原样嵌入
  scripts/                # 来自 EP coder 的环境、初始化、构建、预览资产
  references/             # EP 工程资料及本期图表适配说明
  vendor/                 # EP 组件契约与编码参考，按需加载
```

该结构为职责示意，以 EP 基座实际依赖闭包补齐必需资产；不添加无用途的占位目录。复制时排除归档 zip、生成输出、node_modules、开发缓存及仓库治理文件，不遗漏预览 public/library、环境锁文件或 scripts 的相对依赖。

安装新 skill 后，即使没有 gts-ep-coder 目录、没有本机 D 盘设计源目录，也应能执行完整生成流程。运行指令不得写死调研机器路径。

首版不抽共享包、不增加跨 skill 调度。基座脚本原则上原样复用；必要改动逐项记录，不能机械替换脚本中的所有 gts-ep 名称。允许保留兼容的 index.gts-ep.html、环境池协议及工程标记，新 skill 的注册 name 与目录名使用 gts-ep-charts-coder。

## 4. 维护边界与规则分工

| 内容 | 权威与维护方式 |

| 工程目录、依赖、源码语言、构建与预览协议 | EP 工程基座 |

保留 EP 组件参考供筛选、按钮、表格等使用，但不默认加载整页模板、工作台骨架或所有场景指南。图表布局由分析目标和图表规范决定，不能自动扩充为带导航、统计卡和筛选区的工作台。用户指定的布局和局部修改范围优先。

## 6. EP 图表实现适配

### 6.1 运行时与生命周期

第一版以已有全量 echarts 导入作为直接图表实现路径；vue-echarts 仅在已有接口已确认且适合需求时使用，不同时混用两套实例管理。普通 EP 控件不替代 ECharts 绘图区；不宣称已接入内部业务图表组件。

图表在容器挂载且有有效尺寸后初始化；数据变化更新 option；容器尺寸变化触发 resize；卸载清理实例、监听和观察器。处理空数据、加载状态、隐藏后显示及主题更新；只实现任务涉及的行为，不增加无需求交互。

业务数据通过 src/api 的 Promise 服务获取，mock 存于 src/api/mock，图表组件不直接 import mock。保留原单位、对象身份、缺失语义及数据变换说明。

### 6.2 token、图表色值与主题

页面控件和布局继续采用 scoped Less 与 GTS token，不修改固定主题文件或重绘 EP 内部状态。

ECharts 绘制参数不直接假设支持 CSS var 字符串。需要引用宿主 token 时，在已挂载 DOM 上读取实际计算值后传给 option；主题改变后更新相关 option，保留原有筛选、缩放和选择状态。不得通过销毁所有业务状态来掩盖主题更新问题。

图表规范定义的系列色、轴线、文字及几何参数以所选图表规范为准，不把所有系列替换为品牌色。适配说明应明确：哪些参数映射宿主 token，哪些按图表规范保留，哪些深色参数未定义。未定义部分作为实现建议记录，不能声称来自设计师。

实施时检查 build 对图表 option、CSS 与颜色常量的实际扫描范围。优先兼容现有门禁；若规范要求的值确实被误报，做范围明确的适配并补针对性回归，不全局关闭 token/颜色检查，也不通过字符串拆分或搬文件逃避检查。这项是待验证工程工作，不假定当前必然存在误报。

## 7. 生成、修改与交付流程

沿用 EP 基座：

```text
确认 Node → ensure-env → 新工程 init → 写源码
→ 图标引用新增/变化时 fetch-icons
→ 源码自查、cleanup-starter → build → 交付预览与 HANDOFF
```

- 已有工程原地修改，跳过 init；源码改动后重新 build，不能手工编辑生成 HTML。
- 运行代码写入基座允许目录，主题和预览固定骨架遵从基座编辑边界。
- 环境失败按 HINT 处理；代码错误遵从基座同批交付最多两轮修复重跑的规则，不用切换命令重置额度。
- 最终 build 返回 OK 且相关 WARN 已处理，才能表述“构建通过”。交付 index.gts-ep.html 的可点击预览入口、源码位置及适用验证状态。
- 不承诺 yarn serve、生产构建、独立类型检查或源码包可独立安装，除非对应交付确实提供并执行了相应检查。

## 8. 验证与完成标准

区分 skill 发布验收与每次页面生成，维护回归不变成每页的强制全量检查。

### 8.1 首版发布验收

| 场景 | 必须检查 |
|---|---|
| 基础趋势图 | 挂载与构建、轴/单位、Tooltip、实际渲染 |
| EP 筛选联动图表 | API/mock 边界、筛选与重置真实改变图表、空结果 |
| 多对象平行坐标 | 按上游适用方法实现，数据身份和交互正确；不退化为静态占位 |
| 已有图表局部修改 | 保留原工程和无关内容，最终预览对应最新源码 |
| 容器与主题 | 任务目标尺寸；测试页明确要求时验证深浅切换和 resize |
| 图片导出 | 测试页明确包含导出，实际获得图片并核对内容；代码包导出单独记账 |
| 独立分发 | 不依赖源 skill 或设计源绝对路径，必需库及相对引用完整 |

运行适用的现有 EP 维护测试；只为新增或改动的行为补回归。保留真实命令结果与浏览器证据，编译成功不能替代浏览器挂载验证。缺少环境时标记未验证，不能将发布验收勾为完成。

### 8.2 页面生成时的证据

按本次需求检查编译、实际目标尺寸与承诺交互，局部修改只检查受影响范围。构建、生产构建、类型检查、视觉交互、图片导出、代码包导出和业务接入分别记 PASS、FAIL、未验证或不适用。

可以在缺浏览器能力时交付源码和预览入口，但明确“构建通过，浏览器运行未验证”；适用尺寸和承诺交互有实际证据后，才称“原型已验证”。已知失败不能改写成未验证。不默认加入整套截图、多视口或完整设计盲评；设计效果对比可作为维护评估，不能冒充已做。
